Preparation roadmap

Phase 0 — completed in this scaffold

  • Evidence-backed ecosystem inventory and deep-research report.
  • Strict read-only GIWA Sepolia RPC client with chain-ID fail-close.
  • Token and AMM specification outlines; no Solidity or deployment path.
  • Safety flags and provenance requirements enforced by tests.

Phase 1 — local deterministic prototypes

  • Pin compiler, Foundry, OpenZeppelin, and any AMM dependency by version and license.
  • Implement a plain fixed-supply ERC-20 with invariant, fuzz, access-control, and static-analysis tests. Avoid transfer taxes, hidden minting, blacklist traps, upgradeability, and misleading metadata unless separately justified.
  • Implement or integrate a minimal AMM only after choosing a legally reusable audited base.
  • Run local Anvil tests only; publish a threat model and bytecode reproducibility procedure.

This phase still has no signer, RPC broadcast, or public deployment.

Phase 2 — reviewed GIWA Sepolia deployment candidate

Requires an explicit approval covering exact source revision, contracts, deployer authority, testnet addresses, and cleanup plan. Add a human-operated deployment runbook, not unattended automation. Verify source, roles, constructor arguments, events, invariants, frontend chain guard, and explorer metadata. Use only valueless test assets.

Phase 3 — product experiment

Only after external security review and legal/product approval: multisig and timelock design, incident response, indexer reliability, monitoring, rate-limit strategy, oracle failure policy, bridge assumptions, accessibility, abuse controls, and transparent testnet disclosures.

Phase 4 — public mainnet consideration

Blocked until every gate in MAINNET_GATES.md is evidenced. Private-mainnet access or an accelerator milestone is not a substitute for public availability or production readiness.
