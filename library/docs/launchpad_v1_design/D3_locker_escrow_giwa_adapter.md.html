D3 — PermanentLocker, FeeEscrow, GIWA pool adapter, deployment & security plan (launchpad v1)

Status: design, 2026-09-06 (KST). Nothing here deploys anything. Solidity is illustrative (≥0.8.26, evm_version = cancun), not a full implementation.

Inputs read: docs/launch_research_2026-09-06/01_robinhood_launchpads.md (Pons V2 mechanics, addresses), docs/launch_research_2026-09-06/02_launch_structure_norms.md (dev-buy / sniper norms, licences), docs/launch_research_2026-09-06/05_lp_burn_signal.md §2.c–§3 (what third-party tools can and cannot read on v4), verified sources of PonsV2LaunchLocker (launch/owner_src.json), PonsV2FeeEscrow (launch/sc_0xd3AF…Ac9e.json), ClankerLpLockerFeeConversion.sol, plus the primary docs cited inline.

Fixed product rules this component must honour (from the brief): 1e9 fixed supply, 0% team, 100% to curve/pool; one disclosed atomic dev-buy; 1% trading fee split creator 80 / protocol 20; protocol recipient immutable; creator recipient changeable only through a 3-day timelock; no buyback; no admin key, no pause, no upgrade, no fee switch, no blacklist/mint; liquidity permanently locked; token-side fees retained or burned; 0.0005 ETH creation fee to the protocol recipient; same token address on both chains via CreateX.

0. Decisions in one screen

# Decision Why
D3-1 The locker only custodies. It holds the v4 position NFT (Robinhood) or the pair's non-transferable LP shares (GIWA). It has no claim, no fee logic, no owner, no setFactory. Fees never touch the locker. On v4 fees are taken by the hook at swap time (Pons/Clanker pattern), so a locker collect path is pure attack surface: a DECREASE_LIQUIDITY(0) call is the same ABI as a real decrease. If the locker never calls modifyLiquidities at all, the negative test "locker never calls PositionManager with a write selector" is trivially provable.
D3-2 Position-side fees on v4 are zero by construction: pool fee = 0, hook takes 1% in quote via return-delta; token-side residue (exact-in ETH buys, see §1.4) is burned to 0x…dEaD. Owner rule "token-side fees retained or burned"; removes any need for internal swap-backs (maxInternalPriceImpactBps-style knobs in Pons).
D3-3 FeeEscrow is keyed by token, not by recipient; balances are ledger[token] = {creatorAccrued, protocolAccrued} in that token's quote asset; the creator recipient is per token; the protocol recipient is one immutable address. Per-token accounting is what a 20-line DefiLlama/Dune adapter needs (§2.6). The timelock is naturally per token.
D3-4 Native ETH is the quote on Robinhood (v4 currency0 = address(0)), WETH9 predeploy is the quote on GIWA. The escrow supports both: credit{value} and creditToken. Claims can unwrap WETH9. Avoids the upgradeable aeWETH proxy (0x0Bd7…AD73, TransparentUpgradeableProxy per 04 §1) entirely on Robinhood; GIWA's 0x4200…0006 is an immutable predeploy.
D3-5 GIWA pool = from-scratch LaunchPair (x·y=k, MIT, ~250 lines) with 1% quote-side fee streamed to the escrow, non-transferable LP shares minted once to the locker, sync kept, skim/flash-swap/feeTo/_mintFee removed. v2-core is GPL-3.0 (Uniswap/v2-core/LICENSE); a fork drags 0.3%-on-input semantics, feeTo, skim and flash callbacks we do not want. Third-party v2 routers would mis-quote a 1%-quote-side pair anyway, so a tiny router of our own is required regardless (§3.5).
D3-6 IGraduationTarget makes the curve chain-agnostic: UniswapV4Target (Robinhood) and LaunchPairTarget (GIWA) are the only chain-specific contracts besides the hook. Component 1's curve calls one interface; the address of the target is an immutable in the factory.
D3-7 Same addresses on both chains via CreateX deployCreate3 with sender-guarded, non-cross-chain-protected salts (salt byte 21 = 0x00), so even contracts with chain-specific constructor args (target, locker) land at identical addresses. Hook uses CREATE2 with a mined salt (flag bits) via the Arachnid proxy. CREATE3 addresses depend only on (deployer, salt), not init code — the property we need because PoolManager vs WETH9 arguments differ per chain.
D3-8 Leftover supply at graduation is burned (transferred to 0x…dEaD), not locked. "100% to curve/pool" reads cleanest when no contract holds a bag that GMGN/Bubblemaps could label "insider". Component 1 may override with locker.lockTokenSupply semantics if it needs a reserve; the locker exposes the view either way.
D3-9 After deployment, the only addresses that can do anything are the per-token creator recipient (claim / propose / cancel / accept) and the protocol recipient (claim). Everything else is permissionless or absent. §4.6 lists every callable state-changing function and who can call it.

1. PermanentLocker

1.1 What the locker must and must not be

Reference behaviours observed on-chain (05 §2.c): PonsV2LaunchLocker (0x267444D0…4952, verified) has ABI setFactory (once), lockPosition, lockTokenSupply, isLocked, onERC721Received — no withdraw path, but it still carries Ownable2Step for the one-time setFactory wiring and a renounceOwnership override that reverts. ClankerLpLockerFeeConversion (ClankerLpLockerFeeConversion.sol l.30, 718–740) is Ownable, calls positionManager.modifyLiquidities to collect (DECREASE_LIQUIDITY with liquidity 0), and has withdrawETH/withdrawERC20 onlyOwner sweeps of stray balances. Both are "permanent by reading the source", which is exactly what 05 §3 step 3 says a verifier must do.

Our locker is stricter than both: no owner at all, no factory setter (factory address is an immutable computed before deploy, §4.2), no call into PositionManager, no ERC-20/ETH movement of any kind. The only state transitions are "register custody of position X for token T" (once per token) and the event log.

1.2 Interface

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

/// @notice Custody-only locker. Holds a Uniswap v4 position NFT (Robinhood) or
///         LaunchPair LP shares (GIWA) forever. No owner. No outbound path.
interface IPermanentLocker {
    enum Venue { NONE, UNISWAP_V4, LAUNCH_PAIR }

    struct LockInfo {
        Venue   venue;          // which implementation graduated this token
        address venueContract;  // PositionManager (v4) or the LaunchPair (GIWA)
        uint256 positionId;     // v4 tokenId, or 0 for LaunchPair
        bytes32 poolId;         // v4 PoolId, or keccak256(pair) for LaunchPair
        uint64  lockedAt;       // block.timestamp of graduation
        uint256 burnedSupply;   // tokens sent to 0xdEaD at graduation (D3-8)
    }

    event PositionLocked(address indexed token, Venue indexed venue, address venueContract, uint256 positionId, bytes32 poolId);
    event SupplyBurned(address indexed token, uint256 amount);

    // --- the ONLY state-changing entry points (onlyGraduationTarget, once per token) ---
    function lockV4Position(address token, uint256 tokenId, bytes32 poolId) external;
    function lockPairShares(address token, address pair) external;

    // --- views for third-party verifiers (05 §3 checklist) ---
    function lockInfo(address token) external view returns (LockInfo memory);
    function positionOwner(address token) external view returns (address);   // always address(this) once locked
    function lockedForever(address token) external view returns (bool);      // true once locked; there is no unlock
    function feeRecipients(address token) external view returns (address creator, address protocol, uint16 creatorBps, uint16 protocolBps);
    function feeEscrow() external view returns (address);
    function graduationTarget() external view returns (address);
    function hasWithdrawPath() external pure returns (bool);                 // constant false — documented, greppable
    function supportsInterface(bytes4) external view returns (bool);        // ERC-165: IPermanentLocker + IERC721Receiver
}

feeRecipients is a pass-through read of the escrow (IFeeEscrow.ledger(token)), so a tool that only knows the position owner can walk owner → locker → escrow → recipients without an ABI for the escrow.

1.3 Sketch

contract PermanentLocker is IPermanentLocker, IERC721Receiver {
    address public immutable graduationTarget;   // UniswapV4Target or LaunchPairTarget (CREATE3-precomputed)
    address public immutable positionManager;    // 0x58da…4fA7 on Robinhood; address(0) on GIWA
    IFeeEscrow public immutable feeEscrow;

    mapping(address token => LockInfo) private _info;

    error OnlyGraduationTarget();
    error AlreadyLocked();
    error NotHeld();
    error OnlyPositionManager();

    constructor(address target_, address positionManager_, address escrow_) {
        graduationTarget = target_; positionManager = positionManager_; feeEscrow = IFeeEscrow(escrow_);
    }

    modifier onlyTarget() { if (msg.sender != graduationTarget) revert OnlyGraduationTarget(); _; }

    function lockV4Position(address token, uint256 tokenId, bytes32 poolId) external onlyTarget {
        if (_info[token].venue != Venue.NONE) revert AlreadyLocked();
        if (IERC721(positionManager).ownerOf(tokenId) != address(this)) revert NotHeld();
        _info[token] = LockInfo(Venue.UNISWAP_V4, positionManager, tokenId, poolId, uint64(block.timestamp), 0);
        emit PositionLocked(token, Venue.UNISWAP_V4, positionManager, tokenId, poolId);
    }

    function lockPairShares(address token, address pair) external onlyTarget {
        if (_info[token].venue != Venue.NONE) revert AlreadyLocked();
        if (ILaunchPair(pair).balanceOf(address(this)) == 0 || ILaunchPair(pair).balanceOf(address(this)) != ILaunchPair(pair).totalSupply()) revert NotHeld();
        _info[token] = LockInfo(Venue.LAUNCH_PAIR, pair, 0, keccak256(abi.encodePacked(pair)), uint64(block.timestamp), 0);
        emit PositionLocked(token, Venue.LAUNCH_PAIR, pair, 0, keccak256(abi.encodePacked(pair)));
    }

    /// PositionManager mints with plain `_mint` (no receiver callback) — v4-periphery
    /// PositionManager.sol; this exists only so an explicit safeTransferFrom from the
    /// canonical PositionManager cannot revert. Anything else is refused.
    function onERC721Received(address, address, uint256, bytes calldata) external view returns (bytes4) {
        if (msg.sender != positionManager) revert OnlyPositionManager();
        return IERC721Receiver.onERC721Received.selector;
    }

    function hasWithdrawPath() external pure returns (bool) { return false; }
    // no receive(), no fallback(), no payable functions → ETH cannot even be sent here
}

Notes: - Position mint goes straight to the locker as recipient in MINT_POSITION (v4 docs: "recipient, // Who receives the NFT", https://developers.uniswap.org/docs/protocols/v4/guides/position-manager). PositionManager uses _mint, not _safeMint (v4-periphery PositionManager.sol), so the callback is never part of the graduation path — custody is proven by the ownerOf check, same as Pons. - The locker is deployed with no receive/fallback so accidental ETH cannot accumulate; ERC-20s sent by mistake are simply stuck (intentionally — a rescue is a withdraw path). - positionOwner(token) returns address(this) after lock; a verifier that wants an independent check does PositionManager.ownerOf(lockInfo(token).positionId) == locker (05 §3 step 2) and then greps the verified ABI for the selectors in §1.5 (05 §3 step 3). - On v4 the position's accrued LP fees are always zero because the pool fee is 0 and the hook does not donate. So there is nothing for the locker to collect — that is the answer to "what does the locker even need": custody + a verifiable read surface, nothing else.

1.4 Contract with the hook (component 2) that makes D3-1 possible

The escrow only accepts the quote asset. The hook must therefore take its 1% in quote for every swap direction:

Swap Specified currency Where the hook can take a quote-side fee
Buy, exact-in ETH ETH (specified) beforeSwapReturnDelta on the specified currency (reduce ETH going into the pool) — flag 1 &lt;&lt; 3
Buy, exact-out token token specified, ETH unspecified afterSwapReturnDelta on unspecified (ETH) — flag 1 &lt;&lt; 2
Sell, exact-in token token specified, ETH unspecified afterSwapReturnDelta on ETH output
Sell, exact-out ETH ETH specified beforeSwapReturnDelta on ETH… (exact-out on the specified side raises the user's ETH out; simplest is to disallow exact-out sells in our router and accept that other routers doing it pay fee via the fallback below)

Flag values from Uniswap/v4-core/src/libraries/Hooks.sol (BEFORE_SWAP_FLAG = 1&lt;&lt;7, AFTER_SWAP_FLAG = 1&lt;&lt;6, BEFORE_SWAP_RETURNS_DELTA_FLAG = 1&lt;&lt;3, AFTER_SWAP_RETURNS_DELTA_FLAG = 1&lt;&lt;2; the after-swap hook delta is applied as swapDelta = swapDelta - hookDelta on the unspecified currency). Fallback for any path where the only takeable side is the token: take it and burn (poolManager.take(token, 0xdEaD, amt) — take to an arbitrary recipient is allowed inside the unlock), emitting TokenFeeBurned(token, amount). Pons V2's hook instead runs an internal swap-back bounded by maxInternalPriceImpactBps = 300 (01 §RH-04); we deliberately do not.

The hook credits the escrow inside the same unlock: poolManager.take(CurrencyLibrary.ADDRESS_ZERO, address(this), fee); feeEscrow.credit{value: fee}(token);. The escrow's credit does no external calls, so re-entering the PoolManager is impossible from there.

2. FeeEscrow

2.1 Requirements → design

  • Per-token accrued creator/protocol balances in that token's quote asset (native ETH on Robinhood, WETH9 on GIWA; a future USDG/stock pairing is just another ERC-20 quote — the design allows it, v1 config does not enable it).
  • Pull claim by the recipient; permissionless claimFor(token) push to the current recipient (never to a caller-chosen address).
  • Creator recipient change: propose → 3-day delay → accept by the new recipient (two-step so a typo cannot strand fees) → expires 3 days later if not accepted; current recipient may cancel during the wait. Protocol recipient: immutable.
  • No owner, no pause, no sweep, no arbitrary token rescue. Nothing can move value except to the two recipients.
  • Reentrancy: CEI, nonReentrant, call with all gas (smart-wallet recipients), no transfer().
  • Events designed for a 20-line fees adapter (§2.6).

2.2 Storage and interface

interface IFeeEscrow {
    struct Ledger {
        address quote;            // address(0) = native ETH; else ERC-20 (WETH9 on GIWA)
        address creator;          // current creator recipient
        address pendingCreator;   // proposed new recipient (0 if none)
        uint64  pendingEta;       // earliest accept time
        uint128 creatorAccrued;   // claimable by `creator`
        uint128 protocolAccrued;  // claimable by PROTOCOL
        uint128 creatorLifetime;  // monotonic, for dashboards
        uint128 protocolLifetime;
    }

    // constants
    function PROTOCOL() external view returns (address);         // immutable
    function CREATOR_BPS() external view returns (uint16);       // 8000
    function PROTOCOL_BPS() external view returns (uint16);      // 2000
    function TIMELOCK() external view returns (uint64);          // 3 days
    function ACCEPT_WINDOW() external view returns (uint64);     // 3 days
    function FACTORY() external view returns (address);          // immutable; the only registrar

    // registration (factory, once per token, at launch)
    function register(address token, address quote, address creator) external;

    // crediting (permissionless: caller can only give away value it attaches)
    function credit(address token) external payable;                             // native quote
    function creditToken(address token, uint256 amount) external;                // pulls `ledger.quote` from msg.sender

    // claiming
    function claim(address token, bool unwrap) external returns (uint256);       // msg.sender must be creator or PROTOCOL
    function claimFor(address token, bool unwrap) external returns (uint256 creatorPaid, uint256 protocolPaid); // anyone; pays both recipients
    function claimMany(address[] calldata tokens, bool unwrap) external;         // gas saver for creators with many launches

    // creator recipient timelock
    function proposeCreator(address token, address newCreator) external;         // current creator
    function cancelProposal(address token) external;                             // current creator
    function acceptCreator(address token) external;                              // pendingCreator, after eta, before eta + ACCEPT_WINDOW

    // views
    function ledger(address token) external view returns (Ledger memory);
    function claimable(address token, address who) external view returns (uint256);
}

Why register is factory-only: credit is permissionless (like Pons: "the caller can only ever add value they already attached to the call, so there is no privilege to gate"), but the recipient for a token must be bound exactly once by the launch transaction, otherwise a griefer could register a token address first with themselves as creator. FACTORY is an immutable set at deploy to the CREATE3-precomputed factory address (§4.2); there is no setter.

2.3 Credit and split

uint16 public constant CREATOR_BPS = 8000;
uint16 public constant PROTOCOL_BPS = 2000;

function credit(address token) external payable {
    Ledger storage l = _ledger[token];
    if (l.creator == address(0)) revert NotRegistered();
    if (l.quote != address(0)) revert WrongQuote();
    if (msg.value == 0) return;
    _accrue(token, l, msg.value);
}

function creditToken(address token, uint256 amount) external nonReentrant {
    Ledger storage l = _ledger[token];
    if (l.creator == address(0)) revert NotRegistered();
    if (l.quote == address(0)) revert WrongQuote();
    uint256 before = IERC20(l.quote).balanceOf(address(this));
    IERC20(l.quote).safeTransferFrom(msg.sender, address(this), amount);
    uint256 got = IERC20(l.quote).balanceOf(address(this)) - before;   // fee-on-transfer safe (Pons does the same)
    if (got == 0) return;
    _accrue(token, l, got);
}

function _accrue(address token, Ledger storage l, uint256 amount) private {
    uint256 protocolPart = amount * PROTOCOL_BPS / 10_000;   // rounds down → dust favours the creator
    uint256 creatorPart  = amount - protocolPart;
    l.creatorAccrued  += uint128(creatorPart);
    l.protocolAccrued += uint128(protocolPart);
    l.creatorLifetime += uint128(creatorPart);
    l.protocolLifetime += uint128(protocolPart);
    emit FeesAccrued(token, l.quote, msg.sender, creatorPart, protocolPart);
}

Overflow: uint128 holds 3.4e38 wei; total ETH supply is ~1.2e26 wei — safe, and the packing keeps the ledger to 3 slots.

2.4 Claims (pull and permissionless push)

function claim(address token, bool unwrap) external nonReentrant returns (uint256 amt) {
    Ledger storage l = _ledger[token];
    if (msg.sender == l.creator)       { amt = l.creatorAccrued;  l.creatorAccrued = 0; }
    else if (msg.sender == PROTOCOL)   { amt = l.protocolAccrued; l.protocolAccrued = 0; }
    else revert NotRecipient();
    if (amt == 0) revert NoBalance();
    _pay(l.quote, msg.sender, amt, unwrap);
    emit Claimed(token, msg.sender, msg.sender == l.creator ? Role.CREATOR : Role.PROTOCOL, l.quote, amt);
}

function claimFor(address token, bool unwrap) external nonReentrant returns (uint256 c, uint256 p) {
    Ledger storage l = _ledger[token];
    c = l.creatorAccrued;  p = l.protocolAccrued;
    l.creatorAccrued = 0;  l.protocolAccrued = 0;                      // effects before interactions
    if (c > 0) { _pay(l.quote, l.creator, c, unwrap); emit Claimed(token, l.creator, Role.CREATOR, l.quote, c); }
    if (p > 0) { _pay(l.quote, PROTOCOL, p, unwrap);  emit Claimed(token, PROTOCOL,  Role.PROTOCOL, l.quote, p); }
}

function _pay(address quote, address to, uint256 amt, bool unwrap) private {
    if (quote == address(0)) {
        (bool ok,) = to.call{value: amt}("");                          // full gas: smart wallets / Safes
        if (!ok) revert TransferFailed();
    } else if (unwrap && quote == WETH9) {                             // WETH9 immutable on GIWA (0x4200…0006)
        IWETH9(quote).withdraw(amt);                                   // ETH lands here via receive()
        (bool ok,) = to.call{value: amt}("");
        if (!ok) revert TransferFailed();
    } else {
        IERC20(quote).safeTransfer(to, amt);
    }
}

receive() external payable { if (msg.sender != WETH9) revert DirectEthNotAccepted(); }
  • claimFor cannot redirect: the recipient is read from storage, the caller only pays gas. If a recipient is a contract that reverts, claimFor reverts and nothing is lost — the recipient can still claim themselves after fixing their contract, or move via the timelock.
  • A revert-on-receive creator cannot brick the protocol's share: claimFor pays both, but claim by PROTOCOL pays only its own part and never touches the creator's transfer.
  • receive accepts only WETH9 unwraps, so stray ETH cannot inflate address(this).balance above liabilities in a way anyone could attribute (there is no attribution function anyway).
  • On Robinhood WETH9 immutable is set to address(0) (no unwrap path; native quote) — one bytecode, per-chain constructor arg (fine under CREATE3, §4.2).

2.5 Creator-recipient timelock

uint64 public constant TIMELOCK = 3 days;
uint64 public constant ACCEPT_WINDOW = 3 days;

function proposeCreator(address token, address newCreator) external {
    Ledger storage l = _ledger[token];
    if (msg.sender != l.creator) revert NotRecipient();
    if (newCreator == address(0) || newCreator == l.creator) revert BadRecipient();
    l.pendingCreator = newCreator;
    l.pendingEta = uint64(block.timestamp) + TIMELOCK;
    emit CreatorProposed(token, l.creator, newCreator, l.pendingEta, l.pendingEta + ACCEPT_WINDOW);
}
function cancelProposal(address token) external {
    Ledger storage l = _ledger[token];
    if (msg.sender != l.creator) revert NotRecipient();
    emit CreatorProposalCancelled(token, l.pendingCreator);
    l.pendingCreator = address(0); l.pendingEta = 0;
}
function acceptCreator(address token) external {
    Ledger storage l = _ledger[token];
    if (msg.sender != l.pendingCreator) revert NotPending();
    if (block.timestamp &lt; l.pendingEta) revert TooEarly();
    if (block.timestamp > l.pendingEta + ACCEPT_WINDOW) revert Expired();
    emit CreatorChanged(token, l.creator, msg.sender);
    l.creator = msg.sender; l.pendingCreator = address(0); l.pendingEta = 0;
}

Semantics chosen vs Pons: Pons's docs say "Nothing happens for three days. After that anyone can carry it out, and if no one does within a further three days it expires" and "a creator moving their fees elsewhere during the wait does not call off the proposal" — that clause exists because Pons's proposal is a protocol-side CTO takeover (https://docs.ponsfamily.com/docs/v2). We have no protocol admin, so the only proposer is the creator; the two-step accept by the new wallet replaces "anyone can carry it out" and protects against fat-fingered addresses. Accrued fees during the wait remain claimable by the current recipient — a stolen key can drain accrued fees immediately but must sit on the proposal for 3 days in public; holders and the creator see CreatorProposed and can react (the creator can cancelProposal with the same key, so a theft of the key is a stalemate rather than a silent takeover — this is the honest limit of any single-key design; creators who care should make the recipient a Safe from day one).

Timestamp semantics: on Robinhood (Arbitrum Nitro) block.timestamp is set by the sequencer's clock, may be up to "24 hours earlier than the current time, or one hour in the future", and is monotonic (https://docs.arbitrum.io/build-decentralized-apps/arbitrum-vs-ethereum/block-numbers-and-time). A 3-day lock could therefore be shortened by at most ~1 h by a misbehaving sequencer — acceptable; never use block.number for this on Robinhood because it is the L1 block estimate ("unreliable in the shorter term (minutes)", same page). On GIWA (OP Stack) block.number is the L2 block and blocks are 1 s (docs.giwa.io diffs-ethereum-giwa.md), but we use timestamps on both for one code path.

2.6 Event schema and the 20-line adapter

3.3 LaunchPair semantics

  • token0 = launch token, token1 = quote (WETH9 0x4200…0006); fixed at construction (immutables), so no sorting ambiguity and a fixed ABI for tools.
  • Reserves r0, r1 (uint112 each + uint32 timestamp in one slot, v2 layout so v2-aware indexers can read getReserves()).
  • Fee: 1% of the quote leg, always in quote, always to the escrow:
  • Buy (quote in q, token out t): f = ceil(q / 100); invariant (r1 + q − f) · (r0 − t) ≥ r1 · r0; after the swap r1 += q − f, r0 −= t; f → escrow.creditToken(token, f).
  • Sell (token in x, quote out y to user): y_gross = ceil(y · 100 / 99), f = y_gross − y; invariant (r1 − y_gross) · (r0 + x) ≥ r1 · r0; r1 −= y_gross; y → user, f → escrow.
  • Exactly one of amount0Out/amount1Out may be non-zero (no two-sided swaps, no flash swaps: outputs are transferred after the invariant check on pre-transfer balances, i.e. the caller must have pre-paid input — v2's "optimistic transfer" ordering is dropped, so there is no callback and no re-entrant window).
  • Post-graduation sniper fee (optional, component 1/2 own the curve-side one): openedAt immutable; for block.timestamp − openedAt &lt; SNIPE_SECONDS the quote-side fee on buys is 1% + extra(t) where extra decays 98%→0 over SNIPE_SECONDS (same curve as the hook on Robinhood, §5 lists the timestamp-granularity caveat); the extra goes to the same escrow split. Sells are never surcharged (a 99% sell tax reads as a honeypot to GMGN: 02 §LS-25).
  • LP shares: view-only. name/symbol/decimals/totalSupply/balanceOf exist so Blockscout's token tab and GoPlus-style lp_holders (05 §2.a) show "locker holds 100%"; there is no transfer, transferFrom, approve, permit, burn. mint(to) is callable once, only by the graduation target, only with to == locker (checked against the immutable). Shares minted = sqrt(r0 · r1) (no MINIMUM_LIQUIDITY burn — with a single, permanent, non-transferable depositor the first-depositor inflation attack does not exist; 05 §2.a's "LP burned" semantics are replaced by "LP shares cannot move" which is strictly stronger).
  • sync() kept, skim() removed. sync only raises reserves to balances (donated tokens become permanent liquidity — a feature: "donate to LP"); skim would let anyone extract donations (MEV race, no benefit to us). Note: sync can never lower reserves because tokens only leave via swap, which updates reserves in the same call.
  • Reentrancy: nonReentrant on swap/mint/sync; the only external calls are safeTransfer of a plain ERC-20 and WETH9 (both non-callback), plus escrow.creditToken (no callbacks). Pair holds WETH9, never native ETH → no receive.
  • Views for integrators: getReserves(), getAmountOut(uint256 amountIn, bool quoteIn) → (amountOut, fee), getAmountIn(uint256 amountOut, bool quoteOut) → (amountIn, fee), feeBps() = 100, snipeFeeBps(uint256 ts), escrow(), locker().
function swap(uint256 amount0Out, uint256 amount1Out, address to) external nonReentrant {
    if ((amount0Out == 0) == (amount1Out == 0)) revert OneSideOnly();
    (uint112 r0, uint112 r1,) = getReserves();
    uint256 b0 = token0.balanceOf(address(this));
    uint256 b1 = token1.balanceOf(address(this));
    if (amount0Out > 0) {                                   // BUY: quote already paid in
        uint256 q = b1 - r1;  if (q == 0) revert NoInput();
        uint256 f = _buyFee(q);                             // 1% (+ snipe extra), ceil
        if ((b1 - f) * (b0 - amount0Out) &lt; uint256(r1) * r0) revert K();
        token1.safeTransfer(address(escrow), f);  escrow.creditToken(token0Addr, f);   // escrow pulls via allowance set in constructor; or push+notify variant
        token0.safeTransfer(to, amount0Out);
        _update(b0 - amount0Out, b1 - f);
        emit Swap(msg.sender, 0, q, amount0Out, 0, f, to);
    } else {                                                // SELL: token already paid in
        uint256 x = b0 - r0;  if (x == 0) revert NoInput();
        uint256 yGross = Math.mulDivUp(amount1Out, 100, 99);
        uint256 f = yGross - amount1Out;
        if ((b1 - yGross) * b0 &lt; uint256(r1) * r0) revert K();
        token1.safeTransfer(to, amount1Out);
        token1.safeTransfer(address(escrow), f);  escrow.creditToken(token0Addr, f);
        _update(b0, b1 - yGross);
        emit Swap(msg.sender, x, 0, 0, amount1Out, f, to);
    }
}

(Escrow crediting detail: creditToken pulls from msg.sender; the pair approves the escrow for type(uint256).max of WETH9 in its constructor and calls creditToken(token0Addr, f) without a prior transfer. Either variant is fine; the pull variant keeps the escrow's balance-delta accounting identical for curve, hook and pair.)

3.4 LaunchRouter (stateless, immutable, ~150 lines)

interface ILaunchRouter {
    function buyExactIn(address token, uint256 minOut, address to, uint256 deadline) external payable returns (uint256 out);   // ETH → WETH9 → pair
    function buyExactOut(address token, uint256 amountOut, address to, uint256 deadline) external payable returns (uint256 spent); // refunds excess ETH
    function sellExactIn(address token, uint256 amountIn, uint256 minOut, address to, uint256 deadline, bool unwrap) external returns (uint256 out);
    function sellExactOut(address token, uint256 amountOut, uint256 maxIn, address to, uint256 deadline, bool unwrap) external returns (uint256 spent);
    function quoteBuy(address token, uint256 ethIn) external view returns (uint256 out, uint256 fee);
    function quoteSell(address token, uint256 tokenIn) external view returns (uint256 out, uint256 fee);
    function pairFor(address token) external view returns (address);   // CREATE2 address, no storage
}
  • deadline checked first; slippage via minOut/maxIn; Permit2 (0x0000…8BA3, present on GIWA Sepolia) optional for sells so wallets can do one-signature sells; unwrap returns ETH via WETH9 withdraw (immutable predeploy) then call to to.
  • pairFor is a pure CREATE2 computation over (LaunchPairTarget, salt = bytes32(uint256(uint160(token))), keccak(initcode)), so wallets and GIWATER/Joseon can find the pool without an event index.
  • Router holds nothing between calls; receive accepts ETH only from WETH9. Any ETH left after buyExactOut is refunded in the same call.
  • Because the fee is 1% quote-side, third-party v2 routers will compute wrong amountOut and revert on our K() check (they assume 0.3% on input). That is a known, acceptable limitation for v1: GIWATER is a CL DEX (04 §2.1), Joseon has its own router — neither routes foreign pairs today. If an aggregator appears, it needs a 30-line adapter that calls getAmountOut.

UniswapV4Target (Robinhood)

function graduate(address token, uint256 tokenAmount, uint256 quoteAmount, uint160 sqrtPriceX96)
    external payable onlyFactory returns (bytes32 poolId, address venue)
{
    if (msg.value != quoteAmount) revert BadValue();
    PoolKey memory key = PoolKey({
        currency0: CurrencyLibrary.ADDRESS_ZERO,          // native ETH (&lt; any token address, so always currency0)
        currency1: Currency.wrap(token),
        fee: 0,                                            // hook charges instead (Pons/o1 pattern)
        tickSpacing: TICK_SPACING,                         // 200, matches Pons; full range = [-887200, 887200]
        hooks: IHooks(HOOK)
    });
    poolManager.initialize(key, sqrtPriceX96);             // hook.beforeInitialize checks sender == this target (component 2)
    poolId = PoolId.unwrap(key.toId());

    // Permit2-free path: PositionManager pulls ERC-20s from msg.sender via Permit2 by default,
    // so approve Permit2 for exactly tokenAmount, then execute MINT_POSITION with recipient = locker
    IERC20(token).forceApprove(PERMIT2, tokenAmount);
    IPermit2(PERMIT2).approve(token, address(posm), uint160(tokenAmount), uint48(block.timestamp));
    uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(sqrtPriceX96, MIN_SQRT, MAX_SQRT, quoteAmount, tokenAmount);
    bytes memory actions = abi.encodePacked(uint8(Actions.MINT_POSITION), uint8(Actions.SETTLE_PAIR), uint8(Actions.SWEEP));
    bytes[] memory params = new bytes[](3);
    params[0] = abi.encode(key, MIN_TICK, MAX_TICK, liquidity, quoteAmount, tokenAmount, address(LOCKER), "");
    params[1] = abi.encode(key.currency0, key.currency1);
    params[2] = abi.encode(key.currency0, address(this));          // sweep unspent ETH back here (rounding dust)
    uint256 tokenId = posm.nextTokenId();
    posm.modifyLiquidities{value: quoteAmount}(abi.encode(actions, params), block.timestamp);

    LOCKER.lockV4Position(token, tokenId, poolId);                 // verifies ownerOf == locker
    _forwardDust(token);                                            // ETH dust → escrow.credit(token); token dust → 0xdEaD
    return (poolId, address(poolManager));
}

Action byte values and the "fees are collected by using DECREASE_LIQUIDITY with zero liquidity / SWEEP for native ETH" guidance are from https://developers.uniswap.org/docs/protocols/v4/guides/position-manager. The one-sided rounding leaves wei-level ETH/token dust in the target; it is forwarded (ETH → escrow as fees for the token, tokens → burn), so the target holds nothing after the call and no rescue is ever needed.

Two-position variant (Clanker-style, 02 §(a) "100% into one locked concentrated position") is not used: the curve already discovered a price, and a full-range position at that price is what buyers expect from a Pons-class graduation. A full-range position also means the hook fee is the only fee forever (no LP fee to argue about).

4.2 Addressing: CreateX salts

CreateX (README, https://github.com/pcaversaccio/createx): salt = 20 bytes msg.sender (permissioned deploy protection) ‖ 1 byte cross-chain flag (0x01 on / 0x00 off, >0x01 reverts) ‖ 11 bytes entropy; with sender protection and the flag off, guardedSalt = keccak256(abi.encode(msg.sender, salt)) — chain-independent. With the flag on, keccak256(abi.encode(msg.sender, block.chainid, salt)) — which would give different addresses per chain, so we keep it off.

Two deployment primitives: - deployCreate3(salt, initCode) — address depends on (CreateX, guardedSalt) only. Used for FeeEscrow, PermanentLocker, GraduationTarget, LaunchRouter, Factory/Curve so the addresses match on 4663 and 9134 even though constructor args differ (PoolManager vs WETH9, hook vs none). - The hook needs address flag bits (Hooks.sol: permissions live in the low 14 bits; HookMiner mines a salt against the CREATE2 deployer 0x4e59b44847b379578588920cA78FbF26c0B4956C, https://developers.uniswap.org/docs/protocols/v4/guides/hooks/hook-deployment). Robinhood only; deploy through the Arachnid proxy with the mined salt. Front-run risk: anyone who sees our initcode + salt (e.g. from the testnet deploy) can deploy the identical bytecode at that address on mainnet first — harmless, because constructor args are baked into the initcode and the contract has no owner; the deployer script must simply tolerate "already deployed" and verify extcodehash matches. - Per-launch token: created by the Factory (new LaunchToken{salt: keccak256(abi.encode(creator, creatorNonce, name, symbol))}(name, symbol, curve)) — the factory address and the curve address are identical on both chains, so a creator who launches with the same (name, symbol, nonce) on GIWA gets the same token address as on Robinhood. The factory is the CREATE2 deployer, so no outsider can claim that address.

Circular immutables (locker ↔ target ↔ factory ↔ escrow) are resolved by precomputing every CREATE3 address off-chain (computeCreate3Address(guardedSalt)), passing them as constructor args, and asserting after deployment with a Wiring.check() script that every immutable equals the deployed address — there are no setters to fix a mistake, so a wrong wiring means redeploy under fresh salts (cost: minutes, §4.5).

5.2 Specific attacks to test (each becomes a named test)

  1. Graduation front-run — Robinhood FCFS/no-mempool: the graduating buy and the pool creation are the same tx (component 1), so nobody can initialize the pool key first with a different price… unless they use the same (currency0, currency1, fee 0, tickSpacing, hook) key earlier. Test: an attacker calls poolManager.initialize(key, badPrice) before graduation → must revert in hook.beforeInitialize (sender must be the target, and the token must be a factory token in PRE_GRADUATION state). Also test that a different key (other tickSpacing/fee/hook) for the same token can be created by anyone — it can (v4 is permissionless), and that our lockInfo(token).poolId is what UIs must route to (05 §4 point 6, copycat pools).
  2. Sniper via multiple wallets — the curve-side decay is per-block timestamp, not per wallet, so splitting across wallets does not help; test that N wallets buying in the first second pay the same effective rate, and that the disclosed dev-buy exemption applies to exactly one call from the launch tx (hard cap devBuyCapBps ≤ 500 of supply-equivalent enforced on-chain; a second exempt buy in the same tx reverts). Timestamp granularity: Arbitrum timestamps are whole seconds and 0.1 s blocks share them → a "99% → 0 over 3 s" schedule is a 3–4-step staircase, and everything in second 0 pays the same. Test the staircase explicitly and document it; consider anchoring decay to launchTimestamp + 1 so second 0 is uniformly 99%.
  3. Sell-side griefing — post-graduation sells never carry a surcharge (only buys, §3.3), so a 99%-sell honeypot pattern is impossible; test snipeFeeBps for sells == 0 at all t. On the curve (component 1) the same rule.
  4. Rounding to steal dust — pair: 1-wei buys (f = ceil(1/100) = 1 → the whole wei is fee, output 0 → must not reduce k); sells with amount1Out = 1 (yGross = ceil(100/99) = 2); escrow: protocolPart rounds down so the creator gets the wei; v4 target: SWEEP dust forwarded, never left claimable by a third party. Fuzz 1e6 random micro-trades and assert k never decreases.
  5. Reentrancy via native ETH — escrow claim/claimFor to a malicious recipient that re-enters claim, claimFor, proposeCreator, acceptCreator (all must revert on nonReentrant or see zeroed balances); router unwrap path re-entering sellExactIn; hook crediting escrow inside the PoolManager unlock while an attacker's router re-enters swap (the escrow does no external calls in credit, assert with a call-tracing test).
  6. Hook delta accounting — for each of the four swap shapes assert poolManager currency deltas net to zero after take + credit; assert no hook delta when amountSpecified == 0; assert the hook cannot be tricked into taking a fee on a pool it did not initialize (poolId allowlist populated only by beforeInitialize from the target).
  7. Pair k-invariant — handler with buy/sell/sync/donate/direct-transfer-then-swap; assert r0*r1 monotone non-decreasing and escrow credits == emitted fees; assert a swap whose input was "paid" by a previous donation (balance > reserve) pays the fee on the whole delta (no free trades from stale reserves).
  8. CreateX salt front-running — (a) our sender-guarded CREATE3 salts cannot be used by anyone else (guardedSalt includes msg.sender); test by attempting the deploy from another EOA → different address. (b) Hook via the unguarded Arachnid proxy: an attacker deploys the same initcode first → same address, same bytecode; the deploy script must detect extcodehash and proceed. (c) A different initcode at our precomputed address is impossible (CREATE2 is content-addressed). (d) Per-launch token: the factory is the deployer, so a griefer cannot pre-occupy (name, symbol, nonce) addresses; but a griefer can launch first with the same (name, symbol) under their creator address → different salt, different address; document that "same address on both chains" holds per (creator, nonce, name, symbol), i.e., the owner's own launches.
  9. Escrow registration squatting — only the factory can register; fuzz-callers test; second register for the same token reverts.
  10. Recipient bricking — creator recipient is a contract that reverts on receive: claimFor reverts but PROTOCOL.claim still works; creator can proposeCreator to a working wallet.
  11. Locker as ERC-721 sink — random NFTs safeTransferFrom'd to the locker revert (N9); an attacker cannot make the locker "own" a foreign position to confuse verifiers (lockV4Position is target-only and checks ownerOf).
  12. Gas-limit / DoS on graduation — graduation tx gas on Robinhood v4 measured under --gas-report; the factory's auto-graduate falls back to a permissionless graduate(token) so a gas-limited router cannot strand a completed curve (Pons precedent).
  13. Timestamp drift — fork tests with vm.warp ±1 h around pendingEta to model the Arbitrum sequencer bound; assert the lock can be shortened by at most that bound.
  14. Fee-on-transfer / weird quote — v1 quotes are native ETH and WETH9 only; test that register with any other quote reverts in v1 (allowlist of two), so the escrow's fee-on-transfer defence is belt-and-braces, not load-bearing.
