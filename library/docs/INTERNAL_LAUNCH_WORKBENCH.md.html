내부 종합 런치패드: 빌드 작업 페이지

사이트 통합 · 2026-09-09

오너가 기존 GitHub Pages 사이트에서 모든 작업을 진행하도록 지시했다. 아래의 09-08 로컬 전용 경계를 확장하여, 사이트 첫 화면을 빌드 작업실로 전환한다. overview.html에 이전 상황판을 보존하고 론칭 조사·리서치·노드·스왑풀·수익모델·개발 탭을 양방향으로 연결한다. 기능을 쓰기 위해 localhost 서버를 켤 필요가 없다.

  • solc 0.8.30(약 9.6MB)과 고정된 OpenZeppelin 계약 입력을 동일 사이트에서 제공한다. Web Worker가 실제 컴파일하고 종료되므로 입력 내용이 빌드 서버로 전송되지 않는다.
  • 프로젝트·준비물·예산·관찰 원장은 브라우저 저장소에 남고 GitHub 게시에 포함되지 않는다. 기기 간 이동은 JSON 내보내기/가져오기이며 공동 편집·계정 동기화는 제공하지 않는다.
  • 공식 GIWA/RH RPC는 브라우저에서 직접 읽는다. CORS·오프라인·timeout·체인 불일치는 UNKNOWN으로 표시한다. 임의 RPC URL이나 쓰기 메서드는 받지 않는다.
  • 각 JS·컴파일 입력·compiler binary의 해시를 workbench/manifest.json에 기록한다. deployment.json은 게시 원본 리비전을 기록한다. 이 둘은 사용자 초안과 별개다.
  • 배포 허용 범위는 기존 공개 사이트의 정적 UI·컴파일러·승인된 자료다. 지갑 서명, 컨트랙트 방송, 자금 집행이나 새로운 온체인 발행 승인이 아니다.
npm ci --prefix workbench --ignore-scripts
npm run build:pages --prefix workbench
python3 -m http.server 4173 --bind 127.0.0.1 --directory dashboard

아래는 최초 로컬 구현의 기록이며, 사이트 주소/운영 방식은 이 절이 우선한다.

제품 결정 · 2026-09-08

오너 요청: 리서치 정보창에서 실제 빌드·론칭에 필요한 재료와 실행 흐름을 모으는 내부 종합 런치패드로 전환한다. 시장의 반응을 빠르게 받아 다음 작업에 반영한다. 이 문서는 해당 요청에 따른 CONSTITUTION의 범위 확장 기록이다. 과거 리서치 정책을 현재 제품의 영구적인 구현 금지로 해석하지 않는다.

제품의 기본 화면은 workbench/다. 프로젝트 입력 → 준비물 → 실제 빌드 → 론칭 패키지 → 시장 관찰의 작업 흐름을 제공한다. 공개 dashboard/는 근거 자료실로 유지한다. 코드 구현과 오프라인 검증은 이번 범위다. 실제 온체인 트랜잭션·자금 집행·공개 서비스 배포는 수행하지 않았다. 최신 수수료·플랫폼 설계는 09-06 v1 사양을 따른다. 08월의 zero-revenue 구상을 다시 현재 결정으로 강제하지 않는다.

실행

Node 22 이상, 루트 체크아웃에서:

npm ci --prefix workbench --ignore-scripts
npm start --prefix workbench

http://127.0.0.1:4318을 연다. 저장소 원본이나 .env를 정적 서버로 노출하지 않는다. 기본 포트가 사용 중이면 LAUNCH_WORKBENCH_PORT를 지정할 수 있다. Host와 Origin을 검사하므로 localhost 대신 위의 정확한 주소를 사용한다. 앱은 127.0.0.1에만 바인딩한다.

이름·심볼·체인을 바꾸면 현재 빌드 상태가 무효화된다. 프로젝트 가져오기로 이전의 빌드 성공이나 실행 권한을 복원하지 않는다. 다운로드는 사용자가 직접 시작한다. 토큰 소스 단독 파일은 OpenZeppelin import가 필요하며 전체 빌드 JSON에 모든 의존 소스와 표준 compiler input이 담겨 있다. 수취 커브가 없는 creation bytecode는 서명할 완성된 배포 트랜잭션이 아니다.

가장 빠른 실행 경로

  1. 기존 Pons 경로: 콘텐츠·이미지 원본·예산·수수료 선택 근거를 준비하고 공식 생성 화면에서 값을 재확인한다. Pons는 자체 토큰과 풀을 생성한다. 여기서 만든 LaunchToken을 가져가 거래하는 경로가 아니다. 생성 화면은 2026-09-08에 재확인했다.
  2. 우리 자체 경로: LaunchToken 구현 다음으로 기존 LAUNCHPAD_V1_CONTRACT_DESIGN.md의 팩토리·커브·졸업·영구 잠금 컴포넌트를 구현한다. 전량 배분, 매수·매도, 가격 연속성, 원자적 졸업, fee 원장, LP 인출 불가를 실제 EVM에서 검증한다. 토큰 단독 성공을 전체 프로토콜의 준비 완료로 승격하지 않는다.
  3. 화면 내 직접 실행: 선택한 플랫폼의 정확한 ABI·주소·runtime hash·체인과 최종 파라미터를 결속한 트랜잭션 미리보기, 견적/시뮬레이션, 사용자 지갑 서명, 제출·영수증 대조를 연결한다. 서명 후 응답 유실은 UNKNOWN으로 남기고 자동 재전송하지 않는다.
  4. 출시 후 피드: 확정된 토큰·풀·생성 tx를 관찰 대상으로 등록하고 생성/매수/매도, 홀더 집중, LP·졸업 상태를 소스별로 수집한다. 관찰 시각과 수집 지연을 표시하고 테스트넷 이벤트는 시장 수요에 합산하지 않는다. 이번 버전은 수동 관찰 원장까지다.

Solidity 0.8.30, OpenZeppelin 5.4.0, optimizer 200, Cancun, metadata bytecode hash none를 고정한다. npm lockfile을 체크인하며 solc의 간접 의존성 tmp는 경로 탐색 취약점이 수정된 0.2.7으로 고정한다. Foundry EVM 테스트는 공급 배분·소각·allowance·추가 민트 부재·동일 runtime·잘못된 메타데이터를 검사한다. 보안 감사나 전체 런치패드 E2E를 대신하지 않는다.

서버는 저장소 고정 소스만 컴파일하고 사용자 코드·shell 명령·RPC 주소를 받지 않는다. 빌드 API는 same-origin JSON POST만 허용한다. RPC 메서드는 chainId/blockNumber/gasPrice로 고정된다. 지갑·키·서명·faucet·자금 이동 API가 없다. 내부 초안은 공개 대시보드의 게시 allowlist나 CI 업로드 경로에 포함되지 않는다. localStorage는 암호화 금고가 아니므로 키나 비공개 계정 정보를 입력하지 않는다.
