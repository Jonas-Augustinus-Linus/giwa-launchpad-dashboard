내부 종합 런치패드: 템플릿·지갑 실행

현재 제품 · 2026-09-09

오너는 정보창에서 빌드 작업실로 전환하고, 기존 GitHub Pages 사이트에 전부 통합한 뒤, 재사용할 밈코인 코드와 지갑 연결·가스비·실제 ETH 자금 흐름까지 추가하도록 요청했다. 이 문서와 CONSTITUTION의 마지막 범위 확장이 현재 작업실에 적용된다. 과거 리서치 플래그는 리서치 자료에 그대로 적용하며 사용자 지갑 인터페이스의 영구 금지를 뜻하지 않는다.

운영 주소: https://jonas-augustinus-linus.github.io/giwa-launchpad-dashboard/

사용 흐름

  1. 템플릿 사용: Pons V2 또는 고정 공급 ERC-20. Pons의 검증 배포본 소스·ABI·컴파일 입력을 바로 내려받는다. ERC-20은 OpenZeppelin 5.4.0 기반 코드가 포함돼 있으며 브라우저 solc 0.8.30으로 실제 컴파일한다.
  2. 이름·심볼·공개 콘텐츠: Pons 실행 시 메타데이터 URL과 소개도 온체인에 공개된다. 이미지는 자동 업로드하지 않는다. 현재 설정으로 새 토큰을 만들면 이름·심볼·관찰·준비 완료 상태와 실행 권한은 복사하지 않는다. 브라우저별 최대 20개 초안을 유지한다.
  3. 예산: 초기 매수는 공개 초기 매수 예산을 사용한다. 가스는 실제 RPC 견적으로 계산한다. LP 직접 공급·여유 예산은 현재 거래에 자동으로 포함하지 않는다.
  4. 지갑 연결: EIP-6963 및 EIP-1193 확장 지갑 또는 지갑 앱 내장 브라우저. 계정 연결과 체인 전환은 사용자 클릭으로 시작한다. 개인키·시드·로그인 서버·텔레메트리는 없다.
  5. 실제 조건·비용 확인: 잔액, 체인, 코드, 계약 연결, 생성비, 공급·거래 수수료, ETH 초기 매수와 최소 수령량, 졸업 기준을 읽고 시뮬레이션한다. 이때 지갑 주소와 unsigned calldata에 포함된 생성 입력값은 공식 RPC로 전송된다. 가스 한도와 가스 가격에 각각 20% 여유를 적용한 준비액을 보여준다. 실제 사용액은 지갑과 영수증에서 확인한다.
  6. 검토·서명: 견적은 2분 유효하며 금액·대상·메타데이터 확인 후 지갑에 단일 거래를 요청한다. 서명 전 계정·체인·nonce·잔액·가스·계약 코드·조건을 재조회한다.
  7. 영수증: 전송 해시만으로 성공을 표시하지 않는다. calldata·송신자·value·nonce·체인, canonical block과 영수증 상태, 배포 코드/공급 또는 Pons 이벤트·등록을 대조한다. 공개 RPC 읽기는 300ms 간격으로 진행하며 429는 Retry-After를 존중해 제한적으로 재시도한다. RPC 지연 시 사용자가 해시를 넣어 재확인할 수 있다. 자동 재전송은 없다.
  8. LP 상태: Pons 커브에 쌓인 ETH와 졸업 기준, LP 생성 및 잠금을 별도로 조회한다. 졸업 후 풀 생성이 대기하면 같은 프로젝트·생성 지갑으로 LP 마무리 비용 확인을 실행한다. 이미 모인 자금을 사용하며 추가 예치 없이 가스만 요청한다.

지원하는 두 경로

경로 공급과 ETH 생성 결과
Pons V2 / Robinhood 4663 공급 전량 커브, 생성비 + 선택 초기 매수 + 가스. 추가 크리에이터 세금 0%, 바이백 꺼짐, 수수료 수취는 연결 지갑 토큰·거래 커브, 초기 매수 수령, 졸업 후 Uniswap V4 LP와 영구 잠금
고정 공급 ERC-20 / GIWA Sepolia 91342 또는 Robinhood 4663 10억 개·18 decimals 전량 연결 지갑, 배포 가스만 사용 ERC-20 + Burnable 토큰. 거래 풀·LP는 별도 작업

Pons 초기 매수는 LP 직접 예치가 아니다. 커브가 졸업 기준을 채우면 모인 ETH와 남은 토큰을 풀로 옮긴다. 풀 생성이 지연되면 마무리 거래가 별도로 필요할 수 있다. Pons는 관리자 권한이 있는 외부 프로토콜이다. 자체 v1의 불변 관리자 없는 프로토콜 설계와 구분한다. 제공한 소스의 검증은 보안 감사·무위험·플랫폼 제휴를 의미하지 않는다.

출처와 코드 고정

  • 공식 저장소: https://github.com/ponsdotdev/ponsfamily
  • 실행 ABI와 소스: Sourcify의 실제 배포본. workbench/integrations/pons-v2.json에 관찰 블록·시각·주소·runtime keccak·검증 방법·컴파일러·출처를 기록했다.
  • 팩토리·라우터·deployer 등 9개 계약의 현재 runtime 전체 바이트와 연결을 실행 전 비교한다. 일부 Sourcify match는 executable code가 일치하고 메타데이터가 다른 경우이며 기록에서 exact_match와 구분한다. GraduationGuard는 검증된 팩토리 소스 입력을 solc 0.8.35로 따로 컴파일하여 immutable reference가 없고 runtime 전체 바이트가 같음을 확인했다.
  • Pons GitHub 최신 트리와 배포본은 다를 수 있어 배포본 ABI를 쓴다. 소스 패키지는 원본 SPDX와 메타데이터를 유지한다. Pons를 새로 배포하거나 라이선스를 변경하는 기능이 아니다.
  • workbench/manifest.json은 공개 파일 해시를, deployment.json은 원본 리비전을 기록한다.

저장·실패 처리

프로젝트와 실행 기록은 별도 브라우저 저장소다. 프로젝트 가져오기는 실행 기록이나 서명 권한을 가져오지 않는다. 실행 기록은 사용자 요청으로 각각 내보낸다. 공개 Pages에는 프로젝트·계정·잔액·실행 기록을 넣지 않는다. 동기화·공동 편집과 WalletConnect QR은 미지원이다.

Web Locks로 같은 사이트의 탭 간 전송을 직렬화하고, 지갑 요청 전 실행 의도를 localStorage에 기록한다. 저장 실패·손상·중복/미해결 기록·계정/체인 변화는 실행을 막는다. 서명 취소(4001)는 rejected, 나머지 불명확한 전송 오류는 UNKNOWN으로 남긴다. 지갑이 반환한 해시를 못 저장한 경우 그 해시를 사용자에게 표시한다. 재조회는 읽기 전용이다.

개발·검증

npm ci --prefix workbench --ignore-scripts
npm run build:pages --prefix workbench
npm test --prefix workbench
forge test
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
python3 -m http.server 4173 --bind 127.0.0.1 --directory dashboard

정적 빌드를 먼저 생성한 뒤 npm start --prefix workbench로 기존 loopback 서버를 써도 된다. 공개 사이트는 설치나 별도 서버가 필요 없다. 빌드는 Worker 내부에서 진행한다.

실제 Pons 리허설은 별도 로컬 Anvil 포크로 수행한다. 키를 출력하지 않는 --silent를 사용하고, 테스트 스크립트는 loopback 및 Anvil client version을 확인한 뒤에만 쓰기를 허용한다.

anvil --host 127.0.0.1 --port 8547 --chain-id 4663 \
  --fork-url https://rpc.mainnet.chain.robinhood.com --silent
node workbench/test/fork-rehearsal.mjs

공개 RPC의 과거 상태 보존 기간이 짧으면 새 포크에서 재시작해야 한다. 기록은 workbench/integrations/fork-validation.json에 주소·계정 없이 남긴다. 실제 체인에 보낸 거래는 0건이며 로컬 포크 통과를 실자금 운영·감사 완료로 표현하지 않는다.

English implementation and review notes

The owner authorized a user-operated wallet launch interface on the existing Pages site. The agent never signs, funds, or broadcasts on a live network. The UI supports injected wallet discovery, explicit account/network selection, reviewed unsigned transaction plans, and one user-approved wallet request per operation. Pons V2 creates its own token/curve; the separate fixed-supply ERC-20 deploys its entire supply to the connected account.

Review: bind account, chain, transaction calldata/value/nonce, selected project and quote expiry; pin Pons executable code and dependency wiring; enforce economics digest and a nonzero opening-buy minimum; preserve write-ahead UNKNOWN state and cross-tab locks; verify receipts and distinguish curve creation from actual V4 pool creation/LP locking. Test cancellation, changed inputs/account/chain, insufficient ETH, unavailable RPC, corrupted storage, duplicate requests, ambiguous wallet responses and receipt mismatch. Local fork checks must cover direct ERC-20, Pons creation, atomic opening buy and graduation completion.
