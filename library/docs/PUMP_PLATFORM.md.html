GIWA용 Pump.fun형 플랫폼 청사진

가칭 가보자(GABOJA). Pump.fun을 그대로 복제하는 것이 아니라, GIWA의 Dojang과 up.id를 활용한 trust-first, testnet-first token launch lab으로 설계한다.

현재 판정

조건 상태 이유
EVM·블록·가스 녹색(테스트넷) EVM-equivalent, 약 1초 블록, ETH gas, 살아 있는 RPC
토큰 생성 녹색(테스트넷) 공식 ERC-20 가이드와 검증된 외부 배포 존재
bonding curve 황색 Joseon/Notus가 가능성을 보였지만 새 구현·감사가 필요
graduation AMM 적색 공식 DEX가 없고 기존 외부 migrator/AMM은 운영 기준 미달
지갑 온보딩 적색 MetaMask는 가능하지만 GIWA Wallet은 개발 중
브리지·quote asset 황색/적색 Sepolia bridge는 있으나 mainnet canonical asset·liquidity 미확정
신뢰·신원 녹색(실험) Dojang Verified Address/Code와 up.id라는 차별화 재료 존재
보안 거버넌스 적색 public Security Council/bug bounty 운영 상세가 부족
한국 공개 영업 적색 VASP 신고·ISMS·AML 및 개별 법률 검토 전 실자산 서비스 금지
연말 관심 가설 황색 GASOK·private-mainnet·Demo Day는 촉매지만 수요와 출시일은 미확정

종합: 비공개/제한 공개 GIWA Sepolia prototype은 GO, 실자산 공개 서비스는 NO-GO.

제품 수명주기

creator attest → metadata review → standardized token
       → virtual-reserve curve → completion threshold
       → atomic graduation → canonical AMM → post-launch monitoring
  1. Creator attest: Dojang Verified Address 여부와 up.id를 선택적 공개 badge로 표시한다. 검증되지 않은 creator도 testnet에서 실험할 수 있지만 분명히 구분한다. PII는 수집하거나 onchain에 올리지 않는다.
  2. Metadata review: 이름·ticker·이미지·링크의 사칭, 저작권, 불법·혐오·성적 콘텐츠를 검사한다. UI takedown과 onchain 불변성을 구분하고 투명한 이의제기 로그를 둔다.
  3. Standardized token: factory가 동일한 fixed-supply bytecode만 만든다. hidden mint, tax, blacklist, anti-sell, arbitrary seizure와 proxy는 허용하지 않는다.
  4. Bonding curve: virtual ETH/token reserves와 constant-product quote를 사용하되 실제 ETH reserve, 수수료, rounding, slippage, deadline, reserve solvency를 명시한다. 테스트넷 초기에는 수수료와 경제적 보상을 0으로 둔다.
  5. Completion: market-cap 표시는 조작·oracle 의존성을 만들 수 있으므로, 단순하고 검증 가능한 real quote reserve 또는 sold-token threshold를 사용한다. 값은 local simulation 결과가 나오기 전 정하지 않는다.
  6. Atomic graduation: curve를 영구 종료하고 남은 토큰과 실제 quote reserve를 하나의 canonical AMM으로 원자적 이동한다. 실패 시 상태 전체를 되돌린다. 임의 인출 경로를 두지 않는다.
  7. Post-launch: canonical pool, LP lock/burn 정책, admin/timelock, fee cap, pause와 emergency exit의 정확한 권한을 UI에서 읽을 수 있게 한다.

제안 컨트랙트 경계

  • LaunchToken: 최소 fixed-supply ERC-20 구현
  • TokenFactory: salt와 metadata hash를 기록하고 표준 bytecode만 생성
  • CurveFactory / CurvePool: curve 상태, buy/sell, fee, slippage와 completion
  • GraduationManager: 단 한 번의 원자적 curve→AMM 이동
  • AmmFactory / Pair / Router: canonical pair와 post-graduation swaps
  • FeeVault: protocol/creator fee cap과 투명한 수취인; 테스트넷 초기에는 비활성
  • AttestationAdapter: Dojang/up.id를 읽기만 하며 거래 가능 여부를 중앙 통제하지 않음
  • LaunchRegistry: token, creator, curve, pool, metadata hash와 상태 이벤트 인덱스

지금 이 저장소에는 위 컨트랙트를 구현하지 않는다. 먼저 사양, 수학 모델, threat model, 라이선스 선택과 local property tests를 완료해야 한다.

Pump.fun에서 가져올 것과 버릴 것

가져올 것:

  • 표준 token implementation으로 honeypot 변형을 줄이는 구조
  • virtual curve → 실제 canonical AMM의 명확한 두 단계
  • deterministic quote, 사용자 slippage/deadline, permissionless one-time migration
  • creator/protocol/LP fee를 onchain에서 투명하게 분리하는 모델

그대로 가져오지 않을 것:

  • 생성 수와 거래 수를 성공 KPI로 삼는 방식
  • 초단기 FOMO, 무검증 creator, 가격 상승을 약속하는 UI
  • creator fee가 dump·과잉 발행을 유도하는 경제 설계
  • 라이브스트림을 포함한 무제한 콘텐츠 면적
  • Solana 프로그램·SDK의 직접 복제. EVM용 독립 사양과 라이선스 검토가 필요하다.

Pump.fun 관련 사전연구는 bot-like activity, creator 매도 유인과 반복 초기구매 wallet cohort를 위험으로 제시한다. 공개 재현 데이터가 있는 cohort 연구조차 단순 buyer-flow 상관을 인과로 읽으면 안 된다고 경고한다. 독립 재현이 없는 단일 연구의 graduation 비율은 사업계획 수치에서 제외하고, GABOJA 자체 cohort의 생성→첫 거래→곡선 진행→졸업→7일· 30일 잔존을 직접 측정한다.

GIWA-native 차별화

  • Verified creator, Verified code, Named by up.id badge를 서로 분리한다.
  • creator 검증은 신뢰 신호이지 수익·안전 보증이 아니라고 항상 표시한다.
  • token bytecode, supply, role, fee, curve reserve, graduation destination을 한 화면에서 machine-verifiable하게 보여준다.
  • “가장 많이 만든 체인” 대신 verified-code 비율, 신고 대응 시간, reserve invariant, organic retention, graduation 이후 pool 생존을 품질 KPI로 둔다.
  • raw address나 transaction count를 사람·사용자 수로 부르지 않는다.

지역별 onboarding 원칙

  • 한국어: 업비트 연계 기대를 이용하지 않고, wallet→첫 launch/buy→재방문의 소비자 경험을 실제 funnel로 검증한다.
  • 영어: enterprise·builder 문구와 speculative token 문구를 분리하고, 공식 mainnet·wallet 상태를 항상 표시한다.
  • 중국어: faucet·bridge·UP.ID task를 정확히 번역하되 airdrop, listing, 수익을 암시하지 않는다.
  • 일본어: 전용 test wallet, no native GIWA token, contract verification과 현재 기능 제한을 첫 화면에서 안내한다.

이 구분은 국가별 여론조사가 아니라 2026-08-25 공개 언어권 표본에서 나온 UX 가설이다. X likes·views·followers는 KPI로 사용하지 않는다.

세무 데이터 경계

개인 투자, creator allocation·referral, protocol fee, 법인 treasury를 같은 지갑과 계정으로 섞지 않는다. 모든 가치 이벤트에 UTC 시각, chain ID, tx hash, token·수량, fee, 기능통화 공정가치와 출처, cost-basis lot, 법적 소유자와 거래 목적을 남긴다. 세법상 거주지·법인 실질관리지·고정사업장·고객 소재지가 정해지기 전에는 “DEX라서 어느 나라 세금”이라는 가정을 제품에 넣지 않는다. 상세 비교는 cross-border tax research report를 따른다.

출시 전 결정 게이트

  1. 공개 mainnet과 canonical WETH/ETH·bridge·explorer·RPC가 공식화됨.
  2. graduation AMM의 코드, 라이선스, audit와 admin model이 승인됨.
  3. 외부 audit, invariant/fuzz/differential tests와 reproducible bytecode 통과.
  4. multisig/timelock, monitoring, incident response, content moderation과 takedown 운영 준비.
  5. 한국 대상 여부, VASP 신고, ISMS, AML/Travel Rule, 이용자보호법, 발행·광고·세무에 대한 서비스 구조별 서면 법률 검토.
  6. GIWA/Upbit/Dunamu 비제휴 표시와 상표·도메인 clearance.
  7. 정확한 revision, addresses, curve parameters, fee recipients, funding과 launch window에 대한 인간의 명시적 승인.

수요 가설의 검증 신호

연말 관심 가능성은 thesis이지 현재 사실이 아니다. 다음 신호를 주 단위로 추적한다.

  • 공식 public-mainnet config/RPC/explorer와 GIWA Wallet 공개
  • GASOK Demo Day의 실제 제품, public deployment와 후속 운영
  • canonical bridge asset, stablecoin, production oracle와 첫 credible DEX
  • Dojang/up.id 활성 지갑의 반복 사용(주소 수와 사람 수는 분리)
  • 표준 contract deployer 수, verified source 비율, 7/30일 creator retention
  • Security Council·bug bounty·incident response 상세의 공개

두 개 이상의 핵심 신호가 지연되면 mainnet 일정과 인프라 비용을 줄이고 testnet research 상태를 유지한다.
