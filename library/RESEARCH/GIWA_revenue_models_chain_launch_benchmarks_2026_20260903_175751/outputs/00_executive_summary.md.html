GIWA Launchpad 수익·인프라 리서치 — Executive Summary

기준 시각: 2026-09-03 KST 범위: research-only, 배포·서명·거래·유동성 공급 권한 없음

결론

GIWA Launchpad의 첫 제품은 토큰 발행기가 아니라 Evidence OS + Pool Passport가 적합하다. GIWA는 현재 public mainnet이 아니라 Sepolia가 공개된 상태이고, 경제적 가치가 없는 test token만으로 DEX·NFT·밈코인 수수료 매출을 검증할 수 없다. 반면 노드·RPC·계약 코드·풀 이벤트의 출처, finality, proxy/admin 권한과 주소 충돌을 읽고 보존하는 제품은 지금 바로 research-only로 만들 수 있다. (clm_301, clm_333; src_301, src_303, src_307, src_309)

권장 순서는 다음과 같다. (clm_334, clm_335)

  1. P0 — Evidence OS: provider RPC + canonical raw event + reorg-safe index + Pool Passport.
  2. P1 — Data pilot: 3개 design partner를 대상으로 setup fee와 monitoring MRR의 지불의사 검증. 공개 근거만으로 가격을 확정하지 않는다.
  3. P2 — Vetted launch: public mainnet·canonical asset·감사·IP/소비자 고지가 갖춰진 뒤 목적이 분명한 NFT/프로젝트의 fixed launch fee부터 검토.
  4. P3 — Interface fee: 실제로 UI/API가 라우팅한 유기 거래에만 투명하게 과금.
  5. P4 — Protocol fee / treasury LP: 30/90일 유동성·재방문이 확인된 뒤 서로 다른 원장과 권한으로 심사.
  6. LAST — Memecoin: 시장감시, creator 책임, bot·Sybil 통제와 법률 분류가 없으면 열지 않는다.

노드는 있는가

있다. 현재 공식 node release는 v0.6.0이며 op-reth 2.3.3 + op-node 1.19.1 조합이다. 공식 testnet 사양은 최소 4 core / 8 GB RAM / 500 GB NVMe, 권장 8+ core / 16+ GB RAM / 1+ TB다. Ethereum Sepolia execution RPC와 beacon RPC가 필요하며, full·archive·execution·consensus sync 경로가 문서화돼 있다. 이 표는 Sepolia용이며 mainnet production sizing으로 승격하면 안 된다. (clm_301, clm_302; src_301, src_302, src_303)

온체인 정보를 빠르게 얻는 데 노드는 필요하지만 충분하지 않다. 권장 경로는 provider/private node → raw evidence store → finality/reorg reconciler → normalized index → read API/cache다. Flashblocks의 빠른 pending 상태는 별도 lane에 저장하고 canonical block과 재조정한다. 공개 RPC는 rate-limited이므로 단일 production source로 두지 않는다. (clm_303, clm_304, clm_306; src_305, src_306, src_308, src_332)

스왑 풀을 만들려면

현재 GIWA 공식 레지스트리에는 WETH9·Permit2·Multicall3는 있지만 canonical V3 Factory·Router·Position Manager·Quoter는 등재돼 있지 않다. 따라서 발견된 임의 바이트코드를 “공식 DEX”로 승격하지 않는다. 필요한 제품 묶음은 아래와 같다. (clm_308, clm_309; src_309, src_310, src_312)

  • Core: Factory, Pool, fee tier, tick spacing, oracle observations.
  • Periphery: Router, Quoter, Position Manager, Permit2, Multicall.
  • Assets: canonical WETH/stablecoin, token registry, decimals·tax·mint/freeze 검사.
  • Data: PoolCreated/Initialize/Mint/Burn/Swap/Collect 이벤트 인덱서, tentative/safe/finalized 상태.
  • Trust: Pool Passport, source/code hash, proxy/admin, fee recipient, LP 권한, 감사·라이선스.
  • Operations: governance/timelock, pause·incident plan, monitoring, regression and fork tests.

수익은 네 개의 원장으로 본다

거래량 × fee를 곧바로 우리 매출로 잡지 않는다. (clm_310, clm_318, clm_321)

원장 실제 수취인 GIWA Launchpad 매출 조건
LP revenue 유동성 공급자 또는 voter 운영사가 자기 자본 LP일 때 실현 수수료만; IL/LVR·hedge·gas 차감
Protocol / holder revenue treasury, token holder, burn contract fee switch와 수취 주소가 실제 활성화된 몫만
Interface / launch revenue UI·router·drop 운영사 해당 인터페이스가 만든 거래·민팅과 명시된 fee만
Chain operator revenue sequencer/operator GIWA Launchpad가 체인 운영자라는 계약·권한이 있을 때만

가장 현실적인 초기 후보는 검증 setup + monitoring MRR, 그 다음 vetted launch fixed fee, 이후 interface fee다. NFT primary fee는 일회성이고 secondary royalty는 항상 강제되지 않는다. 자기자본 LP는 fee보다 손실이 클 수 있다. creator coin과 memecoin은 높은 gross fee가 개별 발행 성공을 의미하지 않는다. (clm_322, clm_323, clm_327, clm_332; src_317, src_318, src_340, src_345, src_354, src_355)

벤치마크에서 가져올 것

  • Uniswap: 계약만이 아니라 UI·감사·문서·migration·subgraph를 함께 출시했고, protocol fee는 사용과 유동성이 자란 뒤 켰다. (clm_312, clm_313)
  • Base: builder-only 창과 day-one 앱·Coinbase 배포를 묶었고 수년 뒤에도 활동이 남았다. 공식 campaign 숫자는 self-report이며 사람 수나 Base 운영매출이 아니다. (clm_316, clm_317)
  • Aerodrome: emissions와 voting incentives로 유동성을 점화했다. 높은 점유율을 무보조 수요로 해석하지 않는다. (clm_314, clm_315)
  • Robinhood Chain: 2026-07-01 mainnet과 day-one Uniswap·Pleiades 배포는 확인됐고 9월 초 거래 규모도 컸지만, 관측 기간이 짧고 가스 보조의 부담 주체·기간도 미확인이라 지속 성공으로 판정하지 않는다. (clm_319, clm_320)
  • OpenSea / Zora: primary drop, marketplace, creator, protocol fee를 분리한다. 제품 정책과 contract capability도 분리한다. (clm_322, clm_324, clm_325)
  • Pump / Clanker / Flaunch: curve·canonical pool·creator fee가 cold start를 줄일 수 있으나 버전·풀·수취 주소별로 수익이 달라지고 발행 성공률과 platform fee는 분리된다. (clm_326, clm_327, clm_328, clm_329, clm_330)

Confidence

중간(Moderate). GIWA의 현재 네트워크·노드·공식 계약 표면, 각 프로토콜의 공개 fee schedule과 launch sequence에는 높은 확신이 있다. GIWA의 상업적 지불의사, public mainnet 사양·일정, 실제 canonical DEX와 장기 liquidity에는 공개 근거가 없어 낮은 확신이다.

Refuted

  • 총 DEX 거래량을 launchpad 운영사 매출로 보는 해석.
  • 일반 LP가 받은 모든 fee를 launchpad 매출로 보는 해석.
  • 높은 Pump platform fee가 대부분의 개별 token 성공을 뜻한다는 해석.
  • Robinhood Chain 초기 DEX 흐름의 중심이 tokenized stock이었다는 해석.

Unresolved

  • GIWA public mainnet 일정과 production node 사양.
  • GIWA data/API의 실제 지불의사와 가격대.
  • Robinhood Chain의 30/60/90일 잔존성, RWA 중심성, 가스 보조의 부담 주체·기간.
  • Zora의 pair·chain별 일반화 가능한 단일 fee schedule.
  • Flaunch analytics의 protocol-revenue 분류와 공식 0% share 간 event-level reconciliation.
