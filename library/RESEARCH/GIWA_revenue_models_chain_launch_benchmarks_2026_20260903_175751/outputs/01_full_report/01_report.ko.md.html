GIWA Launchpad: 노드·스왑 풀·수익모델·체인 출시 벤치마크

기준일: 2026-09-03 KST 독자: GIWA Launchpad founder / technical team 판정 범위: research-only; 배포·서명·거래·토큰 발행·유동성 공급 권한 없음

1. 의사결정 요약

지금 만들 것은 “GIWA판 Pump.fun”이 아니라 GIWA Evidence OS다. 공개된 GIWA 상태는 Sepolia의 read-only 검증에는 충분하지만 실매출·유동성·token launch를 증명할 public mainnet은 아니다. 따라서 제품 순서는 데이터 신뢰 계층을 먼저 만들고, public mainnet과 canonical assets가 확인된 뒤 fixed-fee launch, interface fee, protocol fee, permissionless memecoin으로 문을 하나씩 여는 방식이 맞다. (clm_333, clm_334, clm_335; src_301, src_307, src_309, src_320, src_354, src_363)

이 결론은 “수수료가 나오는 기능”과 “그 수수료가 우리에게 귀속되는 사업”을 분리해서 얻었다. DEX 거래량, LP fee, tokenholder revenue, sequencer margin, NFT creator payout은 전부 다른 원장이다. GIWA Launchpad가 실제 수취 주소·계약·고객을 갖지 않는 한 그 숫자는 시장 크기이지 매출이 아니다. (clm_310, clm_318, clm_321; src_315, src_324, src_327, src_338, src_339)

2. GIWA 현재 상태와 노드 사양

2.1 확인된 상태

2026-09-03 현재 공개된 GIWA 네트워크는 GIWA Sepolia, chain ID 91342다. public mainnet 설정은 현재 공개 문서와 node repository에서 확인되지 않았다. 공식 test token은 경제적 가치가 없고 네트워크 reset 가능성도 있으므로, Sepolia의 거래량이나 fee를 현금흐름 전망에 넣을 수 없다. (clm_301, clm_333; src_301, src_303, src_307)

현재 공식 node release v0.6.0은 op-reth 2.3.3과 op-node 1.19.1을 사용하며 op-geth 경로를 제거했다. 이 버전 확인은 “노드를 돌릴 수 있는가”에 답하지만, public mainnet launch date나 production sizing에는 답하지 않는다. (clm_302; src_302, src_303)

2.3 production hardening

현재 shipped entrypoint는 HTTP·WS를 넓게 bind하고 debug·txpool·miner 같은 namespace를 포함한다. 그대로 public Internet에 노출하면 안 된다. 권장 경계는 private subnet, firewall allowlist, TLS/auth reverse proxy, method allowlist, rate limit, separate metrics network와 JWT-protected Engine API다. (clm_305; src_304, src_301)

공개 standard RPC와 Flashblocks endpoint는 테스트·개발용 rate limit가 있다. Robinhood Chain도 production 및 historical indexing에는 provider/archive 경로를 따로 문서화한다. 이 패턴상 “무료 public endpoint 한 개”는 내부 대시보드의 bootstrap에는 쓸 수 있어도 production truth source에는 부족하다. (clm_303; src_301, src_332)

3. 빠른 온체인 정보 아키텍처

노드는 원시 상태 접근점이지 검색 제품 전체가 아니다. 빠른 조회를 위해서는 다음 데이터 흐름이 필요하다. (clm_306)

managed provider ─┐
                  ├─> bounded getLogs backfill ─> raw evidence store
private full node ┘              │
                                 ├─> blockHash/parentHash reorg reconciler
Flashblocks pending lane ────────┘             │
                                               ├─> tentative / safe / finalized
                                               ├─> normalized pool/token/index tables
                                               └─> read API + cache + alert engine

Flashblocks는 약 200ms pending preconfirmation을 제공하지만 canonical finality와 같은 뜻이 아니다. UI에는 “tentative”로 표시하고 뒤에 canonical block으로 reconcile해야 한다. GIWA explorer 자체도 관측 시점에 indexing 완료 플래그가 false였기 때문에 explorer 한 곳만 source of truth로 삼지 않는다. (clm_304, clm_307; src_305, src_308)

3.1 저장해야 할 최소 키

  • Block: number, hash, parentHash, timestamp, status(tentative|safe|finalized).
  • Log: chainId, blockHash, txHash, logIndex, address, topic0..n, raw data.
  • Contract evidence: bytecode hash, verified source state, compiler, proxy implementation, admin/owner, upgrade event.
  • Pool: factory, token0/1, fee tier, tick spacing, creation tx, initialization, current liquidity, fee recipient.
  • Token risk: decimals, total supply, mint/freeze/pause/tax hooks, owner privileges, canonical registry state.
  • Provenance: source URL, observed time, method, response hash, conflicting observation and resolution status.

현재 repository probe가 지원하는 liveness method는 좁은 allowlist에 한정돼 있다. 첫 확장은 read-only eth_getLogs, capability-probed eth_call, transaction receipt backfill이어야 한다. websocket tail은 gap detector와 bounded HTTP backfill 없이는 신뢰하지 않는다.

4. V3 스왑 풀 제품 구조

GIWA 공식 계약 레지스트리는 WETH9·Permit2·Multicall3를 열거하지만 canonical V3 Factory·Router·Position Manager·Quoter를 지정하지 않는다. 따라서 explorer에서 보이는 제3자 V3형 bytecode는 code-visible일 수 있어도 official·audited·canonical이라는 뜻이 아니다. (clm_308; src_309, src_303)

Uniswap 계열 구조를 기준으로 필요한 묶음은 다음과 같다. (clm_309; src_310, src_312)

계층 필수 구성 출시 gate
Core Factory, Pool, tick/fee tier, oracle observation invariant/fork test, audit, source verification
Periphery Router, Quoter, Nonfungible Position Manager, Permit2, Multicall allowance·slippage·deadline UX, revert simulation
Assets canonical WETH, stable pair, token registry canonical issuer, decimals, mint/freeze/tax review
Data PoolCreated/Initialize/Mint/Burn/Swap/Collect index reorg reconciliation, receipt completeness, SLA

4.1 Pool Passport

각 풀을 DISCOVERED → CODE_MATCHED → SOURCE_VERIFIED → OPERATOR_MAPPED → AUDIT_LINKED → CANONICAL의 분리된 상태로 보여준다. 어느 한 상태가 다음 상태를 자동으로 뜻하지 않는다. 주소가 문서·explorer·과거 관측과 충돌하면 QUARANTINED로 두고 swap/LP CTA를 열지 않는다.

4.2 pool launch를 열기 전 필요한 테스트

  • 동일 pair·fee tier 중복 pool 및 spoof factory 탐지.
  • exact-input/output quote와 adversarial token hook simulation.
  • reentrancy, callback validation, price-limit, zero-liquidity, fee-on-transfer rejection.
  • concentrated range 이탈·oracle manipulation·MEV/LVR scenario.
  • upgrade/admin/fee-recipient 변경 alert와 timelock 검증.
  • router/NPM/Permit2 chain-id replay와 allowance 회수 경로.

Uniswap의 v1·v2·v3 출시는 core contract만이 아니라 interface·audit·docs·migration 및 v2 subgraph를 함께 제공했다. GIWA도 pool deployment를 단일 contract task가 아니라 제품 release train으로 다뤄야 한다. (clm_313; src_314, src_364, src_365)

6. DEX 벤치마크

6.1 Uniswap — 사용·이전 경로를 먼저, fee switch는 뒤에

Uniswap v1은 2018년 contracts, UI, audit, whitepaper, docs와 약 3만 달러의 초기 liquidity를 함께 공개했다. v2·v3는 audit·formal verification·interface·migration을 묶었다. holder-directed protocol fee는 초기 growth engine이 아니라 2025-12-28 실행된 governance 이후의 후행 수익화였다. (clm_312, clm_313; src_314, src_328, src_364, src_365)

현행 v2 예시는 0.30%에서 LP 0.25%, protocol 0.05%를 분리하며 v3는 풀별 protocol setting이 동일하지 않다. 총 swap fee와 Labs 매출, UNI holder value capture도 같은 숫자가 아니다. (clm_311; src_311, src_316)

GIWA 전이: migration, source verification, quote/indexing, LP experience가 먼저다. 초기부터 fee switch를 최대화하면 venue가 만들기도 전에 LP를 과세하는 셈이다.

6.2 Aerodrome — incentive market 자체가 제품

Aerodrome은 단순 AMM이 아니라 emissions·gauge voting·voting incentives를 조합해 liquidity 공급과 tokenholder 참여를 연결했다. staked pool fee는 veAERO voters, unstaked liquidity 몫은 LP로 가며 team 5%는 emissions 항목이다. (clm_314; src_313, src_325)

초기 보도와 현재 문서는 incentive를 명시한다. 따라서 높은 Base DEX share를 “보조금 없이 발생한 유기 수요”로 표현할 수 없다. incentives가 revenue보다 큰 기간도 별도 표시해야 한다. (clm_315; src_313, src_325, src_366)

GIWA 전이: incentive 예산은 매출과 상계하고 종료일을 먼저 정한다. subsidized volume과 organic fee-paying cohort를 분리한다.

7. 체인 출시·후속 출시 벤치마크

7.1 Base — builder window와 distribution bundle

Base는 builder-only mainnet을 먼저 열어 contract verification·infra readiness를 만들고, GA 때 앱·service providers·Coinbase surfaces와 Onchain Summer를 묶었다. independent indexed series는 2026년에도 activity가 남아 있음을 보여주므로 단순 launch-day spike 사례는 아니다. (clm_316; src_320, src_321, src_367)

다만 2023년 70만+ mints·26.8만+ wallets, 2024년 $5M+ builder/creator/project mint revenue·2M+ wallets·24M+ assets는 Base 공식 self-report다. wallets는 unique humans가 아니며 $5M은 Base/Coinbase 매출이 아니라 참여자 귀속이다. Coinbase가 filing에서 분류한 Base sequencer revenue와도 별개다. (clm_317, clm_318; src_322, src_323, src_324, src_367)

GIWA 전이: builder-ready → bridge/assets/RPC → day-one apps → distribution campaign → 7/30/90-day retention 순으로 측정한다. NFT 수량보다 cross-app 이동률과 fee-paying repeat user를 본다.

7.2 Robinhood Chain — 출시 traction은 확인, 지속 성공은 보류

Robinhood는 2026-02-10 public testnet 후 2026-07-01 public mainnet을 열었다. day-one에 Uniswap primary public AMM, Pleiades proprietary AMM, wallet·stock-token distribution을 발표했다. 과거 “pre-launch” 메모는 현재 사실을 반영하지 못하므로 mainnet 공식 발표로 갱신했다. (clm_319; src_329, src_330, src_331)

2026-09-03 rolling snapshot은 30일 DEX volume 약 $20.36B, Uniswap share 약 83.2%를 보였다. 이는 큰 launch traction이지만 두 달 남짓의 관측이며 dynamic adapter 수치는 수정될 수 있다. (clm_320; src_331, src_334, src_335)

더 중요한 점은 귀속이다. DEX LP/UNI fee, chain gas residual, app fee와 Robinhood 회계 revenue는 자동 연결되지 않는다. Arbitrum ecosystem revenue share도 별도다. (clm_321; src_315, src_337, src_338, src_339)

GIWA 전이: launch success 판정은 30/60/90일 cohort, stock/RWA·meme·stablecoin 구성, wash-filtered volume과 app retention까지 기다린다. Robinhood가 부담하는 기간형 gas subsidy는 공식 확인되지 않았고, 문서에서 확인되는 것은 개발자가 선택할 수 있는 ERC-4337/Alchemy sponsorship infrastructure다. (src_332)

8. NFT·creator coin 모델

8.1 OpenSea — product fee와 contract capability 분리

2026-05-12 schedule은 NFT sale 1%, hosted primary drop 10%, swap 0%다. hosted payout wallet은 90%를 받고, SeaDrop contract 자체의 fee recipient는 configurable하다. 즉 “10%”는 hosted product policy이지 모든 fork에 박힌 protocol constant가 아니다. (clm_322; src_340, src_341, src_344)

secondary creator earnings는 optional 또는 contract-enforced가 될 수 있고 marketplace 정책 변화의 영향을 받는다. 따라서 royalty를 고정 반복매출로 예측하지 않는다. (clm_323; src_345, src_369)

GIWA 전이: 처음에는 variable GMV take보다 scope가 명확한 deployment·verification·monitoring fixed fee가 감사 가능하다. primary mint는 IP·utility·refund·consumer disclosure gate를 통과한 프로젝트만 받는다.

8.2 Zora — NFT에서 creator coin으로의 pivot

Zora custom pair의 공식 Base·Robinhood 예시는 1% 중 creator 0.70%, protocol 0.25%, Doppler 0.05%다. source·SDK가 공개돼도 Doppler의 BSL production restriction처럼 dependency license는 별도 검토해야 한다. (clm_324, clm_331; src_342, src_347, src_348, src_349)

현재 product는 legacy NFT mint를 deprecated하고 custom-pair coin과 multichain distribution으로 이동했다. 이는 NFT fee의 영속 성공보다 시장에 맞춰 revenue primitive를 바꾼 follow-on launch 사례다. (clm_325; src_343, src_349)

9. Memecoin launchpad 벤치마크

9.1 Pump.fun — 플랫폼 수익과 발행 성공을 분리

공식 current curve schedule은 creation 0, curve swap 1.25% 중 creator 0.30%·protocol 0.95%, graduation 0.015 SOL이다. threshold 뒤 canonical PumpSwap으로 자동·불가역 migration한다. (clm_326; src_350, src_351, src_353)

그러나 832,941 launches를 다룬 2026 preprint의 fast-window graduation 하한은 0.198%였고, 별도 연구는 조정된 early-buyer cohorts를 확인했다. 수치의 window 제한은 지켜야 하지만 방향은 명확하다. 큰 protocol gross fees는 대부분의 creator·holder 성공을 증명하지 않는다. (clm_327; src_350, src_353, src_354, src_355)

9.2 Clanker — 버전별 fee를 섞지 않는다

historical v3.1은 1% Uniswap V3 pool fee 중 20% team, 나머지를 creator/interface에 배분했다. current V4는 선택 creator fee의 20%를 protocol fee로 계산하고 reward를 canonical initial pool에 한정한다. historical traction을 current revenue formula로 그대로 사용하지 않는다. (clm_328; src_356, src_357, src_362)

9.3 Flaunch — fee rights를 NFT로 관리

공식 기본 waterfall은 1% swap fee를 referrer, protocol, creator, bid wall로 보낸다. 현재 official protocol share는 0으로 문서화돼 있지만 pool별 distribution override가 가능하다. creator/community allocation과 fee-management rights가 launch object에 결합되고, 기존 ERC-20 import도 지원하므로 신규 발행뿐 아니라 follow-on liquidity 경로로 볼 수 있다. (clm_329, clm_330; src_358, src_359, src_360, src_370)

독립 dashboard와 official protocol-share 정의가 맞지 않는 항목은 event recipient 기준으로 재조정하기 전까지 대시보드 매출에 넣지 않는다.

9.4 GIWA 원칙

Meme launch를 마지막에 두는 이유는 도덕론이 아니라 측정 가능성이다. volume은 즉시 생겨도 graduation quality, market integrity, user outcome은 약할 수 있다. 미국 SEC staff statement도 사실관계별·비구속적이며 fraud나 disguised security 문제를 제거하지 않는다. (clm_335; src_350, src_354, src_355, src_363)

10. 구현 순서와 gate

P0 — Evidence OS / BUILD NOW

  • provider RPC 두 곳 또는 provider + private full node.
  • append-only raw log와 response hash.
  • tentative/safe/finalized 분리 및 reorg replay test.
  • contract/pool code-state와 주소 충돌 quarantine.
  • Pool Passport read API와 내부 dashboard.

Exit criteria: 7일 gap-free tail, forced-reorg fixture 통과, 모든 카드에 source·observed_at·status, signer와 order method 없음.

P1 — Data pilot / COMMERCIAL GATE

  • design partner 3곳의 반복 query와 alert use case.
  • setup, monitoring, API usage를 분리 견적.
  • false-positive·data latency·incident response 비용 측정.

Exit criteria: 2개 이상의 paid-intent 또는 계약 가능한 반복 수요, provider/storage/on-call 포함 contribution margin 가설. 가격 자체는 공개 자료에서 확정하지 않는다.

P2 — Vetted launch / MAINNET GATE

  • 목적·IP·token rights가 분명한 NFT 또는 project launch.
  • fixed setup fee 우선, variable fee는 수취 주소와 refund policy 공개.
  • canonical WETH/stable/bridge/oracle/explorer와 audit 확인.

Exit criteria: 법률·소비자 review, source verification, runbook, 30일 creator support budget.

P3 — Interface fee / LIQUIDITY GATE

  • 우리 router/UI가 실제 route한 거래만 계측.
  • quote에는 pool fee와 interface fee를 분리 표시.
  • 0 bps control cohort와 repeat use·price impact 측정.

Exit criteria: 30/90일 organic volume, depth, repeat user, 무료 대체 UI 대비 retention.

P4 — Protocol fee 및 treasury LP / SEPARATE AUTHORITY

  • protocol fee: governance, timelock, recipient, emergency process.
  • treasury LP: 별도 custody·risk budget·hedge·exit policy.
  • 어느 쪽도 다른 쪽의 수익으로 상계하지 않는다.

LAST — Permissionless memecoin

  • creator identity/attestation, content moderation, bot/Sybil surveillance.
  • canonical graduation pool과 LP/fee-right ownership 공개.
  • suspicious cohort, wash volume, graduation funnel, post-graduation survival 측정.

Exit criteria: 별도 법률 승인, incident reserve, abuse kill-switch, organic post-graduation cohort.
