GIWA 생태계와 토큰·DEX 준비성 심층 리서치

기준일: 2026-08-25 (KST) 연구 성격: research_only=true, strategy_consumption_allowed=false, order_input=false

1. 결론과 의사결정

GIWA에서 토큰과 DEX를 만드는 기술 자체는 이미 테스트넷에서 가능하다. GIWA 공식 가이드는 OpenZeppelin ERC-20을 Foundry 또는 Hardhat으로 개발·테스트·배포·검증하는 절차를 제공한다. Blockscout와 공개 RPC에서는 외부 런치패드·AMM 컨트랙트가 실제 코드로 존재하고 일부는 소스까지 검증된 것을 확인했다. (GIWA, n.d., “토큰 컨트랙트 발행하기”; src_008; Blockscout/Codex, 2026-08-25, “GIWA Sepolia observation”; src_004) [검증 원장: clm_004, clm_005]

하지만 이것은 지금 메인넷 밈코인이나 운영 DEX를 출시해도 된다는 뜻이 아니다. 공식 문서와 공식 노드 저장소는 일반 개발자가 접속할 공개 네트워크를 Sepolia로 안내하고 메인넷과 GIWA Wallet을 개발 중으로 표시한다. GASOK의 공개 일정도 2026년 8~9월 제품화·private mainnet 배포, 10월 데모데이를 가리킨다. 따라서 현재는 공개 메인넷 운영 단계가 아니라 출시 준비 단계로 분류해야 한다. (GIWA, n.d., “GIWA 체인에 연결하기”; src_001; GIWA, 2026, “GASOK”; src_024; Optimism Foundation, 2026-05-04; src_043) [검증 원장: clm_001, clm_014]

권고는 세 단계다.

  1. 지금: 근거 수집, 로컬 전용 컨트랙트 설계·테스트, 읽기 전용 테스트넷 관찰.
  2. 별도 승인 후: 가치 없는 GIWA Sepolia 데모를 정확한 소스 리비전으로 제한 배포.
  3. 공개 메인넷·보안·거버넌스·유동성 근거가 모두 생긴 뒤: 독립 감사와 법률/제품 승인을 거쳐 메인넷 후보를 새로 심사.

현재 저장소는 1단계까지만 구현한다.

2. 범위와 방법

조사는 공식 문서, GIWA GitHub와 배포 아티팩트, 제공사 1차 문서, 제3자 프로젝트 소스, 그리고 2026-08-25 공개 JSON-RPC와 Blockscout의 읽기 전용 관찰을 사용했다. 검색 결과의 숫자나 프로젝트 자기소개만으로 채택하지 않고, 네트워크 상태·코드 존재·소스 검증 여부를 교차 확인했다. 동적 관찰의 원문은 artifacts/live_observation_2026-08-25.json에 해시와 함께 고정했다. (GIWA/Codex, 2026-08-25, JSON-RPC observation; src_003; Blockscout/Codex, 2026-08-25; src_004)

증거 등급상 공식 문서와 공식 GitHub도 미래 약속이 아니라 현재 구현을 말할 때만 확정 근거로 사용했다. 외부 제공사·프로젝트 문서는 그 제공사의 주장 범위에서만 인정했고, 공식성·안전성·채택으로 확대하지 않았다. 테스트넷 이용약관은 테스트 토큰의 무가치성, 운영 지속성 부재, 리셋·롤백·중단 가능성을 명시하므로 모든 결론의 상한으로 적용했다. (Dunamu, n.d., “GIWA 테스트넷 이용약관”; src_007) [검증 원장: clm_015]

3. 현재 네트워크

3.1 공개 상태와 실행 환경

GIWA Sepolia는 OP Stack 기반 EVM-equivalent L2이며 체인 ID 91342 (0x164ce), 가스 자산 ETH, 목표 블록 간격 약 1초, 블록 가스 한도 60M을 사용한다. 시퀀서는 L2 블록을 먼저 만들며 공개 L2 mempool은 없다. 공식 문서는 unsafe, safe, finalized 헤드를 구분한다. (GIWA, n.d., “이더리움과 GIWA의 차이”; src_010; ethereum-lists, 2026, chain metadata; src_041) [검증 원장: clm_002]

읽기 전용 실측에서 표준 RPC는 reth/v2.3.0 계열 clientVersion, 체인 ID 91342, syncing=false를 반환했고 2026-08-25 05:16:20 KST의 블록 34,257,464를 제공했다. 표준 RPC와 Flashblocks RPC가 같은 체인과 클라이언트를 보고하되 관찰 시점에 한 블록 차이가 난 것은 정상적인 헤드 시점 차이로 해석했다. 이 결과는 당시 liveness만 증명하며 SLA나 미래 가용성을 뜻하지 않는다. (GIWA/Codex, 2026-08-25; src_003)

3.2 Karst와 노드 경로

Karst Upgrade 19는 2026-07-06 적용되었다. 공지는 Osaka EVM, L2CM, OPCMv2, 단일 트랜잭션 가스 상한 16,777,216, op-reth 전용 전환, kona-client와 permissioned fault proof를 설명한다. 공식 chain-operations 저장소에는 실제 멀티시그 승인·실행 아티팩트가 있고 현재 RPC도 op-reth를 응답하므로 예정 공지 이상의 실행 근거가 있다. (GIWA, 2026-07-02, “Upgrade 19”; src_005; GIWA, 2026-07-06, chain operations; src_006; GIWA/Codex, 2026-08-25; src_003) [검증 원장: clm_003]

op-geth 지원은 2026-05-31 종료되었다. 스냅샷 페이지에 남은 Geth 경로는 현재 운영 지침으로 사용하면 안 되고, 최신 giwa-io/node의 .env.sepolia와 op-reth 경로가 우선한다. (GIWA, 2026-04-16, “op-geth 지원 종료”; src_038; GIWA, n.d., “노드 스냅샷”; src_039; GIWA, 2026-07-13, node repository; src_002) [검증 원장: clm_018]

공식 표준 RPC와 Flashblocks RPC는 모두 개발용 rate-limited endpoint다. Flashblocks는 최대 약 200ms 주기의 preconfirmation을 제공하지만 finality가 아니며, 지속 수집이나 서비스에는 자체 op-reth 노드 또는 검토된 제공자가 필요하다. 공식 노드 문서는 최소 4코어/8GB RAM/500GB SSD, 권장 8코어 이상/16GB RAM/1TB NVMe를 제시한다. (GIWA, n.d., “GIWA 체인에 연결하기”; src_001; GIWA, n.d., “Flashblocks”; src_011; GIWA, 2026-07-13, node repository; src_002; GIWA, n.d., “노드 서비스”; src_021) [검증 원장: clm_021]

운영 모델에는 중앙화·권한 가정이 남는다. 공개 자료상 primary sequencer는 Dunamu가 운영하고 Optimism 측 백업 경로가 계획되며, 현재 단일 시퀀서와 permissioned fault proof를 전제로 해야 한다. 그러므로 거래·브리지 UI는 preconfirmation, unsafe, safe, finalized를 동일시하면 안 된다. (Optimism Foundation, 2026-05-04; src_043; GIWA, n.d., network differences; src_010; GIWA, 2026-07-02; src_005) [검증 원장: clm_019]

3.3 기본 인프라

GIWA Sepolia에는 Safe, Multicall3, deterministic deployer, Permit2, ERC-4337 v0.6/v0.7 EntryPoint, EAS, WETH9, L1/L2 bridge와 messenger, mintable-token factory 같은 표준 컨트랙트가 문서화되어 있다. 표본 주소들에 대한 eth_getCode도 비어 있지 않았다. (GIWA, n.d., “GIWA 컨트랙트”; src_009; GIWA/Codex, 2026-08-25; src_003) [검증 원장: clm_020]

4. 공식 생태계

4.1 Dojang과 up.id

Dojang은 EAS 기반 공식 신뢰 계층이다. Verified Address, Balance Root, Verified Balance, Verified Code 스키마와 테스트넷 주소가 공개되어 있고, giwa-io/dojang 소스 및 @giwa-io/dojang-contracts 0.5.0 패키지가 제공된다. 2026-08-25 관찰에서 핵심 주소에 바이트코드도 있었다. (GIWA, n.d., “Dojang”; src_012; GIWA, n.d., “Dojang 컨트랙트”; src_013; GIWA, 2026-06-16, dojang source; src_014; GIWA, 2026-05-14, npm package; src_015; GIWA/Codex, 2026-08-25; src_003) [검증 원장: clm_008]

up.id는 ENS 기반 username.up.id 이름이며 Verified Address 자격에 종속된다. 문서상 지갑당 하나, 양도 불가 SBT, 유예·회수 규칙을 가진다. 이는 온보딩과 신뢰 표현에 쓸 수 있는 GIWA-native 구성요소지만, 거래 권한이나 신용 보증으로 바꾸어 해석해서는 안 된다. (GIWA, n.d., “Upbit Web3 Names”; src_016; fangTiger, 2026-07-29, GiwaIntent; src_030) [검증 원장: clm_009]

4.2 오라클, 노드, 브리지

GIWA 오라클 문서는 Pyth와 RedStone을 열거한다. Pyth의 GIWA Sepolia 주소 0x2880…7B43은 Pyth 문서와 일치하고 실측 bytecode도 존재한다. RedStone은 push와 pull 양 경로를 GIWA 문서 및 자사 발표에서 설명한다. 제공사 지원은 가용성·feed 범위· 신선도·오류 모드를 별도 검증해야 하며 이 저장소에서는 전략 입력으로 허용하지 않는다. (GIWA, n.d., “오라클”; src_017; Pyth, n.d., contract addresses; src_018; RedStone, 2025-11-19; src_019; GIWA/Codex, 2026-08-25; src_003) [검증 원장: clm_010, clm_011]

Nodit은 GIWA 공식 문서와 Nodit 문서 양쪽에서 GIWA Sepolia 노드·데이터 API 및 faucet 지원이 확인된다. 이것은 테스트넷 제공자 지원 근거이지 메인넷 SLA는 아니다. (GIWA, n.d., “노드 서비스”; src_021; Nodit, n.d., “Faucets”; src_022) [검증 원장: clm_012]

공식 브리지 문서는 Superbridge 기반 Sepolia UI를 안내하고 L2→L1 출금에 약 7일이 걸린다고 설명한다. 표준 OP Stack bridge/messenger 주소에는 코드가 있다. 테스트 토큰 이동 경로는 존재하지만 메인넷 canonical asset이나 경제적 유동성의 증거는 아니다. (GIWA, n.d., “브릿지”; src_023; GIWA, n.d., “컨트랙트”; src_009; GIWA/Codex, 2026-08-25; src_003) [검증 원장: clm_013]

4.3 개발 프로그램과 문서 공백

GASOK은 DeFi/RWA, Consumer/Social, GIWA-native, AI/Web3, Mass Adoption 트랙을 두고 최대 10만 달러의 조건부 지원을 소개한다. 공개 일정은 6~7월 MVP/Testnet, 8~9월 Productize와 private mainnet deployment, 10월 KBW Demo Day다. 그러나 프로그램은 선정·혜택·지원이 Upbit 거래지원과 무관하다고 명시한다. (GIWA, 2026, “GASOK”; src_024) [검증 원장: clm_017]

Giwa Toolkit, Upbit Oracle, 일반 Cross-chain, Security Council, Bug Bounty 페이지는 현재 공개 페이지에서 구현 세부를 충분히 제공하지 않는다. 페이지 제목이 있다는 사실과 사용 가능한 제품·API·운영 제도가 있다는 판단을 분리해야 한다. (GIWA, n.d., Toolkit; src_033; Upbit Oracle; src_034; Cross-chain; src_035; Security Council; src_036; Bug Bounty; src_037; documentation index; src_046)

5. 제3자 생태계

5.1 Joseon.fun

Joseon.fun은 GIWA Sepolia용 독립 토큰 런처와 AMM이다. API health가 체인 ID 91342를 응답하며 2026-07-28 V4의 LaunchFactory, SwapFactory, Router, MigrationManager, Registry, Locker, WETH9 주소들이 공개되어 있다. Blockscout 실측에서는 이 핵심 컨트랙트들이 fully verified로 확인되었다. (Joseon.fun, 2026-07-28, “Network”; src_025; Joseon.fun, 2026-08-25, health endpoint; src_027; Blockscout/Codex, 2026-08-25; src_004)

동시에 프로젝트 자체 안전 문서는 testnet only, 외부 감사 없음, admin key 단일 지갑, 현재 스택의 live graduation 증거 부재, mainnet 전 multisig 필요를 밝힌다. 누구나 토큰을 만들 수 있고 프로젝트가 토큰을 심사하지 않으므로, 이는 기술 실험 증거이지 재사용 승인이나 투자 신뢰의 근거가 아니다. (Joseon.fun, 2026-07-28, “Safety and risk”; src_026) [검증 원장: clm_006]

5.2 Notus

Notus는 pump-style bonding curve 런치패드 프로토타입이며 GIWA Sepolia V7.1 주소의 소스 검증이 확인된다. 하지만 저장소에는 라이선스가 없고 GIWA DEX migrator, 실제 지갑 E2E, 메인넷 permission 정책, 법률 검토가 TODO다. 소스가 보인다는 것과 안전·합법적으로 재사용 가능하다는 것은 별개다. (giupy997, 2026-07-31, Notus repository; src_028; Blockscout/Codex, 2026-08-25; src_004) [검증 원장: clm_007]

5.3 GiwaIntent와 기타 실험

GiwaIntent는 Dojang과 up.id를 request-to-pay 흐름에 결합했고 두 핵심 컨트랙트가 Blockscout에서 검증되어 있다. GIWA 고유 신뢰 도구의 실제 조합 사례로는 유용하지만, 독립 감사, 라이선스, 지속 호스팅, 실제 지갑 KPI 근거는 완료되지 않았다. (fangTiger, 2026-07-29, GiwaIntent; src_030; Blockscout/Codex, 2026-08-25; src_004) [검증 원장: clm_022]

giwa-dex.vercel.app 연계 저장소는 ETH–INDSR 한 페어만 다루는 작은 데모다. 연결된 AMM과 토큰은 explorer에서 소스 검증되지 않았고, 저장소는 두 커밋, README·라이선스 부재, 설정 내 오래된 chain-ID 오타가 있어 재사용 기반으로 부적합하다. (vikitoshi, 2025-09-10, Giwa-Dex; src_029; Blockscout/Codex, 2026-08-25; src_004) [검증 원장: clm_023]

SODAX는 GIWA testnet 연결과 cross-network execution 준비를 발표했지만, 자사 글에서도 intent 구조가 테스트넷에서는 실질적으로 완전 동작하지 않는다고 밝힌다. 따라서 제공사 발표 수준의 탐색 항목으로만 남긴다. (SODAX Team, 2026-06-01; src_031) GIWA Eco는 독립 커뮤니티 디렉터리로 보이며 화면 간 프로젝트 수가 일관되지 않으므로 공식 GASOK roster나 채택 증거로 쓰지 않았다. (GIWA Eco, 2026-06-26; src_032)

6. 토큰·DEX 가능성

6.1 밈코인 또는 ERC-20

기술 판정은 Yes, 출시 판정은 Testnet-only다. 공식 가이드의 Solidity/OpenZeppelin 절차와 제3자 검증 컨트랙트는 GIWA Sepolia에서 ERC-20 생성·배포·검증이 가능함을 뒷받침한다. 다만 테스트넷 토큰은 무가치하고, 유료 판매·무승인 상업 홍보와 CEX/DEX 연계를 보장하지 않는 이용약관을 따라야 한다. (GIWA, n.d., token guide; src_008; Dunamu, n.d., testnet terms; src_007)

별도 네이티브 $GIWA 토큰을 선매수해야 한다는 주장은 공식 FAQ와 충돌한다. 공식 계획은 가스에 ETH를 쓰고 별도의 GIWA 네이티브 토큰을 만들지 않는 것이다. giwa.markets 같은 독립 사이트는 스스로 GIWA/Upbit/Dunamu와 무관하다고 표시하므로 공식 근거가 아니다. (GIWA, n.d., FAQ; src_045; ethereum-lists, 2026; src_041; GIWA.MARKETS, 2026; src_042) [검증 원장: clm_016]

안전한 첫 토큰 사양은 고정 공급, 단순 ERC-20, 투명한 테스트넷 표기, hidden mint·tax· blacklist·anti-sell·proxy가 없는 구조다. 이름과 티커는 GIWA/Upbit/Dunamu의 공식성을 암시하지 않아야 한다. 이것은 본 리서치가 제안하는 설계 원칙이며 아직 구현이나 배포가 아니다.

6.2 자체 DEX

EVM 수준에서는 가능하지만 새로 검증해야 한다. 표준 컨트랙트, EVM 호환성, 실제 제3자 AMM의 코드 존재는 custom AMM 구현 가능성을 입증한다. 반면 공식 문서 인덱스에는 공식 DEX나 런치패드 제품이 확인되지 않았고, 발견된 구현은 감사·라이선스·관리자·E2E 공백 때문에 그대로 포크할 기준을 충족하지 못한다. (GIWA, n.d., contracts; src_009; GIWA, n.d., documentation index; src_046; Joseon.fun, 2026-07-28; src_026; giupy997, 2026-07-31; src_028; vikitoshi, 2025-09-10; src_029)

로컬 AMM 후보는 공급량·reserve 보존, k 불변식, 수수료·반올림, reentrancy, 악성 토큰, slippage/deadline, LP 회계, donation/skim, oracle manipulation을 상태 기반 fuzz와 differential test로 먼저 통과해야 한다. 공개 mempool이 없고 Flashblocks가 빠르더라도 시퀀서 순서 결정과 preconfirmation 취소·재조직 위험은 남는다. (GIWA, n.d., network differences; src_010; GIWA, n.d., Flashblocks; src_011)

6.3 Pump.fun형 플랫폼 적합성

Pump.fun의 공식 구조는 단순 token factory가 아니다. 새 token을 표준 형태로 만들고, virtual token/quote reserves를 가진 constant-product bonding curve에서 즉시 buy/sell을 제공하며, real reserve가 완료 조건에 도달하면 curve를 닫고 실제 자산을 canonical AMM으로 permissionless하게 옮긴다. 사용자 보호 면에서는 max quote in·min quote out 같은 slippage bound, migration의 one-time/idempotent 성질, post-graduation pool과 fee/admin surface가 함께 필요하다. (Pump.fun, 2026-07-15, Pump Program; src_047; PumpSwap; src_048; Pump.fun, 2026-05-20, fees; src_049) [검증 원장: clm_024]

GIWA에서는 이를 EVM의 TokenFactory → CurvePool → GraduationManager → AMM Pair로 나누어 구현할 수 있다. 1초 블록, EVM 호환성, Flashblocks, 표준 predeploy와 이미 존재하는 외부 curve/AMM은 testnet prototype의 기술 조건을 뒷받침한다. Dojang Verified Address/ Code와 up.id는 Solana 복제본이 아닌 GIWA-native 신뢰 badge를 만들 수 있는 차별점이다. (GIWA, n.d., network differences; src_010; Flashblocks; src_011; Dojang; src_012; up.id; src_016; Joseon.fun; src_025; Notus; src_028)

그러나 현재 readiness는 다음처럼 갈린다.

6.4 Solana형 밈코인 온보딩의 제품 조건

Pump.fun 모델의 장점은 creator가 초기 LP를 직접 준비하지 않아도 curve가 가격발견과 실제 quote reserve 축적을 시작한다는 점이다. 하지만 발행 장벽이 낮을수록 churn, bot, sniper, 사칭과 콘텐츠 문제가 커진다. 공개 사전논문과 재현 데이터는 여러 launch의 첫 구매 구간에 반복 등장하는 wallet cohort를 탐지했지만, activity-matched placebo가 더 큰 겉보기 효과를 보여 raw early-buyer 지표의 인과 해석을 경고한다. 따라서 “sniper가 붙었다”, “초기 거래가 많다”를 품질이나 성공으로 표시해서는 안 된다. (Kamat, 2026-07-02; src_056; RED-COHORT dataset, 2026-07-24; src_073) [검증 원장: clm_038]

단일 사전논문이 제시한 특정 기간 graduation 비율은 독립 재현 근거가 부족해 검증 allowlist에서 제외했다. GABOJA의 사업계획에는 외부 시장의 단일 비율 대신 자체 테스트넷 cohort의 생성→첫 거래→곡선 진행→졸업→7일·30일 잔존을 직접 측정해야 한다.

가보자 후보의 제품 원칙은 다음과 같다.

  • 100% 표준 fixed-supply bytecode; hidden mint, tax, blacklist, anti-sell, proxy 금지.
  • creator pre-allocation·creator fee는 기본 0으로 시작하고, 경제 설계·법률 검토 후 별도 결정.
  • Dojang Verified Address, Verified Code, up.id를 각각 표시하되 수익·안전 보증으로 표현하지 않음.
  • 가격·시가총액보다 real reserve, sold supply, fee, admin, destination pool을 그대로 공개.
  • atomic one-time graduation; 실패 시 전체 revert; 임의 liquidity withdrawal 경로 금지.
  • 이름·ticker·이미지·링크·댓글의 사칭/유해물 moderation과 투명한 이의제기 절차.

Pump.fun도 하루 수백 개 stream을 내린다고 밝힐 만큼 user-generated content 운영면이 크다. 토큰 컨트랙트만 안전해도 플랫폼이 안전한 것은 아니다. (Pump.fun, n.d., Community Notice; src_053) [검증 원장: clm_029]

6.5 한국 규제 경계

가상자산이용자보호법 제2조는 영업으로 하는 가상자산 매매·교환, 정해진 이전, 보관·관리, 그리고 매매·교환의 중개·알선·대행을 가상자산사업자 행위로 정의한다. 금융위원회·FIU는 2026-06-24 한국인을 대상으로 영업하는 국내외 사업자가 ISMS 등 요건을 갖춰 신고해야 하며 미신고 영업에 형사처벌·접속차단 등 제재가 가능하다고 재강조했다. (대한민국, 가상자산이용자보호법 제2조; src_050; 금융위원회·FIU, 2026-06-24; src_051)

8. 준비한 저장소와 로드맵

새 저장소의 현재 기능은 다음과 같다.

  • data/ecosystem.json: 12개 핵심 항목을 공식·제공사·제3자로 구분하고 근거 ID와 안전 플래그를 강제한다.
  • src/giwa_lab/rpc.py: 6개 읽기 전용 메서드만 allowlist하고 signing/send/debug/ personal 계열은 전송 전에 거부한다.
  • src/giwa_lab/probe.py: 체인 ID가 91342가 아니면 다른 호출 전에 실패하고, liveness와 선택 주소의 bytecode 존재만 JSON으로 출력한다.
  • contracts/specs/: 최소 ERC-20과 AMM의 보안·테스트 요구사항만 정의하며 Solidity와 배포 기능은 두지 않는다.
  • docs/PUMP_PLATFORM.md: 가보자 제품 수명주기, 컨트랙트 경계, GIWA-native 차별화, moderation·법률·출시 게이트를 정의한다.
  • data/brand_candidates.json, docs/BRAND_DOMAINS.md: 시점 고정 RDAP 결과와 브랜드 순위를 기록하고 구매·상표 확인이 없었음을 명시한다.
  • docs/ROADMAP.md, docs/MAINNET_GATES.md: 로컬 prototype → 별도 승인된 testnet → 보안 검토 → 공개 mainnet 재심사의 순서를 명시한다.

다음 작업은 로컬 Anvil에서만 수행할 수 있는 결정론적 컨트랙트 prototype이다. 컴파일러와 OpenZeppelin/AMM 의존성·라이선스를 고정하고 unit/invariant/fuzz/static-analysis/ reproducible-build를 통과시키는 단계다. 이 단계에도 signer와 RPC broadcast는 필요 없다.

테스트넷 배포 후보는 그 뒤 별도 의사결정이다. 정확한 Git revision, 컨트랙트·생성자 인자, 테스트넷 deployer와 권한, explorer 검증, valueless disclosure, 종료 계획을 사람이 승인해야 한다. mainnet은 동일 코드를 단순 재배포하는 단계가 아니라 새 위협 모델과 감사가 필요한 별도 제품이다.

11. Unresolved

다음은 현재 증거로 확정하지 않는다.

  • 공개 메인넷 날짜와 누구나 사용할 수 있는 mainnet RPC·explorer·bridge의 최종 사양.
  • GIWA가 직접 운영하는 DEX 또는 token launchpad의 존재.
  • Toolkit, Upbit Oracle, 일반 cross-chain 페이지의 사용 가능한 공개 API·컨트랙트.
  • Security Council 구성·권한·절차와 공개 bug bounty의 실운영 상세.
  • GASOK의 공신력 있는 전체 선발팀 명단과 최종 숫자.
  • 메인넷 canonical stablecoin, liquidity venue, 생산 oracle 주소와 failure policy.
  • Chainlink의 제공사 발표가 GIWA 공식 지원 매트릭스에 포함되는지 여부. Chainlink는 Data Streams의 GIWA Sepolia 지원을 발표했지만 GIWA oracle 페이지에는 현재 열거되지 않는다. (Chainlink, 2026-02-26; src_020; GIWA, n.d., oracles; src_017)
  • 정확한 가보자 운영 구조가 한국 규제상 어떤 신고·인가·통제 조합을 요구하는지. 기능별 위험은 확인했지만 개별 서면 법률 의견은 없다.
  • 공개 메인넷 전후의 관심이 실제 반복 사용자와 지속 유동성으로 이어질지. GASOK·Demo Day는 촉매지만 수요 보장은 아니다.
  • 추천 이름의 상표·법인명·SNS 권리와 registrar 최종 결제 가격. RDAP만 확인했다.
  • 국가별 X 긍정률, engagement 총량과 작성자의 실제 국적·거주지. 전체 표본과 위치·봇 제거 근거가 없다.
  • 단일 Pump.fun 사전논문의 특정 기간 graduation 비율. 독립 재현 없이 GIWA 전망이나 사업계획 수치로 쓰지 않는다.

12. Refuted

다음 해석은 현재 근거와 충돌하므로 채택하지 않는다.

  • 독립 사이트가 표시하는 동명 자산을 GIWA 공식 네이티브 토큰으로 간주하거나 선매수를 권하는 해석. 공식 FAQ는 별도 네이티브 토큰 계획이 없고 ETH gas를 쓴다고 설명한다.
  • GASOK 참여·지원·지갑 기회가 Upbit 거래지원을 보장한다는 해석. 프로그램이 직접 무관하다고 밝힌다.
  • 테스트넷 explorer의 누적 transaction/address 숫자를 같은 수의 사용자나 경제적 채택으로 간주하는 해석.
  • 최신 Karst 네트워크에서 op-geth가 계속 지원된다는 해석. 공식 지원 종료 공지와 현재 op-reth 경로가 반대 증거다.
  • EVM 호환성과 빠른 블록 하나만으로 대규모 상업 onboarding 준비가 끝났다는 해석.
  • registry에서 비어 보이는 도메인이 곧 독점적 브랜드 권리를 준다는 해석.
  • 한국어·영어·중국어·일본어 게시물 표본을 각 국가 전체의 여론 또는 작성자 국적으로 간주하는 해석.
